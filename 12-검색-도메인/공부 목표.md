# 공부 목표: 상품 검색 도메인

> 상태: 시작 전 · 작성일: 2026-09-09 · 실습 도메인: 검색어·필터·관련도·검색 데이터 갱신

## 학습 목적

고객이 입력한 검색어와 조건으로 적절한 상품을 찾고, 결과의 관련성·최신성·응답 성능을 근거로 개선한다. 상품 원본과 검색용 데이터가 달라지는 이유를 이해하고 누락·지연·장애를 복구한다.

검색의 관련도는 검색어와 상품이 얼마나 잘 맞는지를 뜻한다. 랭킹의 인기는 구매·조회 같은 신호에 기반한다. 두 신호를 조합할 수 있지만 초기에는 따로 검증하여 잘못된 검색 결과가 인기 점수로 가려지지 않도록 한다.

이 문서는 앞으로 수행할 실습 목표다. 검색 엔진의 도입이나 성능 개선이 완료되었다는 의미는 아니다.

## 전체 흐름

1. 상품 원본에서 검색에 필요한 이름·브랜드·카테고리·가격·공개 상태를 구성한다.
2. 검색어를 검증·분석하고 필터·정렬 조건과 함께 검색한다.
3. 관련 상품 후보를 찾고 관련도 또는 명시된 정렬 기준으로 순서를 정한다.
4. 고객에게 공개 가능한 결과와 페이지 정보를 반환한다.
5. 상품 변경을 검색용 데이터에 반영하고 검색 품질·지연·누락을 측정한다.

## 핵심 개념별 목표

- [ ] **탐색 요구와 API 계약:** 빈 검색어, 최대 길이, 카테고리·브랜드·가격 필터, 정렬, 결과 없음, 페이지 크기의 동작을 정의한다.
- [ ] **문자열 검색과 전문 검색:** SQL LIKE에 의한 문자열 비교와 텍스트를 분석해 찾는 전문 검색의 차이를 예제로 설명한다. 데이터량과 요구에 따라 적용 범위를 판단한다.
- [ ] **역색인과 텍스트 분석:** 역색인은 단어에서 해당 단어를 포함하는 문서를 찾는 구조다. 텍스트를 검색 단위인 토큰으로 나누는 과정, 한국어 형태소 분석, 정규화, 동의어를 구분한다.
- [ ] **관련도와 필터:** 필터는 충족할 조건을 제한하며 관련도 점수는 조건을 통과한 결과의 순서에 쓰일 수 있다. 단어 빈도·희소성·문서 길이를 사용하는 BM25의 기본 의도를 이해한다.
- [ ] **검색 품질:** 중요한 검색어와 기대 상품으로 평가셋을 만든다. 상위 K개 중 적절한 결과의 비율인 Precision@K와 첫 적절한 결과의 위치 등을 비교한다.
- [ ] **필터별 결과 수:** 브랜드·가격대별 결과 수를 보여주는 패싯을 이해한다. 현재 선택한 필터를 집계에 적용하는 범위와 비공개 상품 제외 규칙을 정의한다.
- [ ] **정렬과 페이지:** 같은 점수·가격의 보조 정렬을 정의한다. 검색 데이터 변경 중 페이지 중복·누락을 재현하고 깊은 페이지의 비용과 조회 시점 고정의 필요성을 비교한다.
- [ ] **검색용 데이터와 동기화:** 원본 DB 변경과 검색 반영 사이의 지연을 이해한다. 중복·순서 역전·삭제 이후 오래된 갱신이 도착하는 상황을 처리한다.
- [ ] **재색인과 운영:** 재색인은 검색용 데이터를 다시 만드는 작업이다. 새 검색 데이터 생성·검증·조회 대상 전환·실패 복구의 절차를 설명한다.

## 초기 실습 정책

다음은 연습을 위한 선택이다. 사용 중인 쇼핑몰의 정책이나 특정 검색 엔진의 기본 설정을 뜻하지 않는다.

- 하나의 쇼핑몰에서 상품명·브랜드·카테고리를 검색 대상으로 삼는다. 개인화·광고·다국어는 후속 과제로 둔다.
- 빈 검색어는 필터 기반 전체 상품 탐색으로 취급한다. 입력 길이와 페이지 크기의 상한을 명시하고 초과 요청은 오류로 응답한다.
- 초기는 DB 기반 검색으로 시작해 정답 사례와 한계를 기록한다. 다음 단계에서 전문 검색 엔진을 비교하여 분석기·관련도·반영 지연을 실습한다.
- 검색 엔진 단계의 기본 정렬은 관련도이며 상품명·브랜드 필드의 가중치는 평가셋으로 조정한다. 가격순을 선택하면 가격과 상품 ID로 정렬하며 인기 가중치는 우선 적용하지 않는다.
- 공개·판매 중 상품을 대상으로 하고 품절은 표시한다. 비공개·판매 중지·삭제는 제외한다. 관리자의 공개 중지가 검색 데이터에 늦게 반영될 수 있으므로 응답 전 현재 공개 상태를 일괄 확인한다.
- 초기에는 검색 후보 상위 20개에서 최종 공개 상태를 검사한다. 제외된 후보 때문에 결과가 20개보다 적을 수 있고, 다음 페이지는 후보 기준 위치를 사용한다. 정확한 공개 결과 총건수와 패싯은 후속 확장 시 일관성 정책까지 정의한다.
- 공개 상태 확인에 실패하면 명시적 오류로 응답한다. 검색 장애를 정상적인 ‘검색 결과 없음’으로 바꾸지 않는다.
- 일반 상품 변경의 검색 반영 목표는 실습용으로 60초 이내로 둔다. 사건 전달 지연과 검색 가능해지는 지연을 함께 측정하며, 공개 차단은 위의 별도 검사로 다룬다.

## 단계별 실습

1. 가상의 상품 데이터와 검색어 20개 이상을 만든다. 정확한 상품명, 브랜드명, 띄어쓰기 변형, 동의어, 오타, 복합 조건, 결과 없음 사례의 기대 결과와 허용 범위를 작성한다.
2. SQL 기반 검색·필터·정렬을 구현하고 실행 계획과 응답 시간을 기록한다. 상품별 추가 조회 없이 최종 공개 상태를 확인한다.
3. 전문 검색 엔진으로 같은 데이터셋을 비교한다. 한국어 토큰과 동의어 처리 결과를 관찰하고 상위 검색 결과의 품질을 전후 비교한다. 오타 허용으로 무관한 결과가 늘어나는지도 확인한다.
4. 동일 가격·점수의 상품과 조회 중 상품 갱신을 넣어 페이지 결과를 확인한다. Elasticsearch를 선택하면 search_after와 조회 시점을 고정하는 PIT의 적용 조건을 실험한다.
5. 원본 DB 변경 후 검색 반영까지의 흐름을 만든다. 삭제·갱신의 순서 역전과 중복 전달을 재현하고 버전 비교 또는 원본 재조회 정책을 검증한다.
6. 새로운 검색 구조로 전체 재색인하는 동안 변경된 상품도 최종 결과에 반영되게 한다. 검증 후 조회 대상을 전환하고 실패 시 복구한다.
7. 전시 화면의 검색창과 필터에 연결한다. 검색 지연, 결과 없음 비율, 품질 평가 결과, 변경 반영 지연을 함께 기록한다.

## 스스로 설명할 질문

- ‘수분 크림’과 ‘수분크림’의 결과가 달라지는 이유를 어디서 확인하는가?
- SQL LIKE로 충분한 요구와 검색 엔진 도입을 검토할 요구는 무엇인가?
- 인기 상품이 검색어와 무관한데도 상위에 오르면 어떤 기준을 수정해야 하는가?
- 상품 저장이 성공했는데 검색에 아직 안 보이는 원인은 무엇인가?
- 삭제된 상품의 오래된 갱신 사건이 도착하면 다시 검색되는 것을 어떻게 막는가?
- 검색 후 비공개 상품을 제거하면 페이지 크기·총건수·필터별 결과 수에 어떤 영향을 주는가?
- 재색인 중 새로 수정된 상품을 놓치지 않으려면 무엇을 기록하고 따라잡아야 하는가?

## 완료 기준

- [ ] 검색어·필터·정렬·빈 결과·오류에 대한 API 계약과 예시를 작성한다.
- [ ] 고정된 평가셋으로 SQL 기반 검색과 전문 검색의 품질·비용을 비교한다.
- [ ] 공개 상태·동률 정렬·갱신 중 페이지 조회를 정책대로 검증한다.
- [ ] 중복·역순·삭제 사건에서도 검색 데이터가 오래된 상태로 되돌아가지 않도록 한다.
- [ ] 재색인·전환·복구를 재현하고 데이터 최신성과 누락을 검증한다.
- [ ] 성능 수치와 검색 품질, 반영 지연을 구분해 기록한다.
