# 공부 목표: Java 기본기와 실행 원리

> 상태: 시작 전 · 작성일: 2026-09-09 · 목표 수준: Java·Spring 미들급 개발자의 독립적인 구현·검증·문제 해결

## 학습 목적

자료구조와 객체 상태, 메모리와 스레드의 동작을 근거로 Java 코드를 작성하고 문제의 원인을 설명한다.

**학습 우선순위:** 기초 점검 후 약한 부분을 보완한다. 트랜잭션·동시성 학습과 병행한다.

## 학습 환경

- Java / Spring Boot 버전: 미정
- DB / 데이터 접근 기술: 미정
- 실습 코드 위치: 미정

현재 프로젝트의 기술과 버전을 적은 뒤 시작한다. 확인하지 않은 동작은 가정으로 표시하고 실습으로 검증한다.

## 핵심 개념별 목표

- [ ] **컬렉션과 시간 복잡도**: List·Set·Map의 순서, 중복, 조회·변경 특성을 이해하고 작업에 맞는 구현체를 선택한다.
- [ ] **객체 동등성**: equals와 hashCode의 계약을 이해하고, 해시 기반 컬렉션의 키 상태를 변경했을 때의 문제를 설명한다.
- [ ] **불변성과 객체 설계**: 객체 상태 변경을 제한하는 이유와 방어적 복사의 필요성을 설명한다. record도 내부 가변 객체까지 자동으로 불변으로 만들지는 않는다는 점을 확인한다.
- [ ] **예외와 자원 관리**: 검사 예외와 비검사 예외의 차이, 오류 전파와 복구 책임, try-with-resources의 자원 해제 흐름을 이해한다.
- [ ] **제네릭과 Stream**: 제네릭의 타입 안전성, 지연 실행과 최종 연산을 이해한다. 부수 효과가 있는 Stream 코드와 병렬 처리의 위험을 판단한다.
- [ ] **스레드와 공유 상태**: 원자성은 작업이 분리되어 관찰되지 않는 성질이고, 가시성은 변경이 다른 스레드에 보이는 성질임을 구분한다. synchronized·volatile·원자적 연산을 비교한다.
- [ ] **JVM과 진단**: Java 실행 환경인 JVM의 힙·스택, 메모리를 회수하는 GC, 스레드 풀과 작업 대기열을 설명한다. 스레드 덤프와 메모리 지표를 읽는다.

## 실습 과제

1. equals와 hashCode 구현에 따라 HashSet의 중복 판정이 달라지는 예제를 작성한다.
2. 여러 스레드가 같은 카운터를 증가시키게 하고, 일반 변수·volatile·동기화·원자적 변수의 결과를 비교한다. 우연히 성공한 실행만으로 안전성을 판단하지 않는다.
3. 제한된 스레드 풀에 느린 작업을 제출하고 작업 대기와 거부 상황을 관찰한다. 스레드 덤프로 대기 위치를 확인한다.
