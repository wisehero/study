# 목록의 부재를 빈 결과로 표현

학습일: 2026-09-11 · 학습 순서 02 · 책의 아이템 54

정상 조회 결과가 0개라면 null 대신 빈 목록을 반환한다. 호출자는 별도의 null 검사 없이 순회할 수 있다. 조회 실패를 빈 목록으로 바꾸면 상품이 없는 것과 장애를 구분할 수 없으므로 실패는 예외 등으로 전달한다.

## 반환값의 약속

- 상품이 있으면 수정 가능한 목록, 없으면 수정 불가능한 목록을 반환하는 방식은 피한다. 같은 호출 코드의 add가 데이터 유무에 따라 성공하거나 실패하기 때문이다.
- 수정 가능한 결과가 필요하면 빈 결과를 포함해 ArrayList 복사본을 반환할 수 있다.
- 목록 구조의 수정을 금지하려면 빈 결과를 포함해 List.copyOf로 반환할 수 있다. 수정 시 UnsupportedOperationException이 발생한다.
- 내부 목록을 그대로 노출하면 호출자의 clear가 내부 상태도 바꿀 수 있다. 목록 복사로 구조는 분리할 수 있지만, 가변 원소 객체는 여전히 공유된다.
- 카테고리는 있지만 상품이 없는 경우와 카테고리 자체가 없는 경우를 구분할지는 API 계약으로 정한다. 이번 예제는 후자를 예외로 구분한다.

## 실습의 한계

수정할 수 없는 목록이 원소까지 불변으로 만드는 것은 아니다. List.copyOf는 null 원소도 허용하지 않는다. 이번 실습의 입력 계약은 null이 아닌 목록과 상품 원소를 전제로 한다. 목록 복사는 원소 수에 비례하는 비용이 들며, 내부 목록 공유는 비용이 적지만 외부 변경 위험이 있다.
