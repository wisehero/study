# 실패 전달 실습 기록

검증일: 2026-09-11 · Java 21 toolchain · Gradle Wrapper · JUnit

## 읽는 순서

1. [SearchExample](../../../java-lab/src/main/java/dev/study/javalab/effectiveJava/chapter06/SearchExample.java)의 hiddenFailure와 search를 비교한다.
2. [SearchExampleTest](../../../java-lab/src/test/java/dev/study/javalab/effectiveJava/chapter06/SearchExampleTest.java)의 세 테스트에서 호출자가 받는 결과를 확인한다.

SearchClient는 검색 시스템의 응답을 모의하는 작은 인터페이스다. 정상 응답은 null이 아닌 상품명 목록을 반환한다고 가정한다. 실제 네트워크 대신 람다로 목록이나 IOException(입출력 실패를 나타내는 검사 예외)을 발생시킨다.

## 검증

Java Lab에서 `./gradlew test`를 실행했다. 새 테스트 3개와 기존 25개, 전체 28개가 통과했다.

- 잘못된 예제에서는 정상적인 빈 결과와 연결 실패 모두 빈 목록으로 끝난다.
- 개선 예제는 정상 빈 결과와 상품이 있는 결과를 그대로 전달한다.
- 실패 시 IllegalStateException을 전달하고 getCause()에 원래 IOException 객체가 보존되는지 확인했다.

3번 테스트의 assertThrows가 실패를 인식하는 호출자 역할을 한다. 로그만 남기는 별도 예제는 코드가 길어지지 않도록 생략했다. 메서드가 정상 반환한다면 호출자가 실패를 모른다는 문제는 빈 목록 대체 예제와 같다.

## 적용 범위와 대안

복구할 일이 없다면 IOException을 throws로 선언해 그대로 전달할 수도 있다. 이번 예제는 실패에 작업 의미를 붙이고 원인을 보존하는 변환을 보여준다. 실제 애플리케이션에서는 계층에 맞는 예외 타입을 선택한다.

소스 한 파일과 테스트 한 파일만 추가했다. 실제 검색 연결, 재시도, 중복 요청 제어와 로깅은 구현하지 않았다. 직접 반환값이나 원인 인자를 바꾸어 테스트 결과를 설명하는 학습 확인은 남아 있다.
