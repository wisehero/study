# 이펙티브 Java: 우선 학습할 30선

작성일: 2026-09-10 · 기준: Joshua Bloch, Effective Java 3판

## 목적과 선정 기준

3년차 Java·Spring 개발자가 코드 작성·리뷰·장애 분석에서 활용할 원칙 30개를 정리한다. 앞선 대화의 20개를 유지하고, 추가로 고른 10개를 같은 순서로 연결했다. 공식 30선이나 중요도·난이도 순위는 아니다.

목표는 규칙을 외우는 것이 아니라 적용 이유, 예외와 비용을 설명하고 잘못 적용했을 때의 문제를 재현하는 것이다. 각 제목·설명·실습은 우리 학습을 위해 작성했으며 책 본문을 대체하는 요약은 아니다. 새 코드 구현과 학습 완료 처리는 포함하지 않았다.

1. **동등성과 컬렉션:** 아이템 10·11을 기존 Java Lab 예제로 시작한다.

3. **금액과 실패 처리:** 60·61, 9·69·73·77을 상품·주문·검색 사례로 확인한다.
4. **객체와 API 설계:** 1·2·5·18·20·34·54·55를 생성·의존성·반환 계약에 적용한다.
5. **타입과 데이터 처리:** 26·27·31·46으로 제네릭과 변환 흐름을 정리한다.
6. **동시성과 운영 비용:** 78·80·48·7·67을 공유 상태, 작업 실행, 메모리와 측정으로 연결한다.

학습 순서는 실무의 필요에 따라 조정한다. 특히 쇼핑몰 실습에서는 금액 정확성(60), 실패 처리(73·77), 병렬화(48)를 우선 보완할 수 있다.

## 서로 연결해 볼 기준

- equals와 hashCode는 함께 확인하고, 해시 컬렉션에 넣은 뒤 기준 필드를 변경하는 경우도 다룬다.
- final·record·복사의 보장 범위를 구분한다. 내부에 가변 객체가 있으면 별도 확인이 필요하다.
- Optional과 빈 목록은 각각 단일 결과 부재와 정상적인 목록의 결과 없음을 표현한다. 시스템 실패와 혼동하지 않는다.
- 실패 원자성은 객체의 상태에 대한 성질이다. DB 롤백과 외부 시스템의 효과까지 동일하게 보장되는 것은 아니다.
- 공유 데이터 보호와 작업 실행 정책을 구분한다. 실행기나 병렬 Stream을 사용하는 것만으로 업무 데이터가 안전해지지 않는다.
- 금액의 단위·소수점·반올림과 입력 누락의 의미를 정한 뒤 수 타입을 선택한다.

## 실습과 기록 관리

- [Java Lab](../../java-lab/README.md)에서 언어와 표준 라이브러리의 동작을 먼저 확인한다.
- [Spring Lab](../../spring-lab/README.md)에서는 빈·HTTP·DB·트랜잭션과 연결된 차이를 검증한다.
- 각 아이템 이름의 폴더에 `공부 목표.md`를 두고, 학습하면서 노트와 실습 기록을 추가한다.
- 상태는 `시작 전 → 학습 중 → 검증 중 → 완료`로 관리하고 목록과 상세 문서를 함께 갱신한다.
- 기록에는 **문제 → 환경 → 예상 결과 → 재현 → 개선 → 검증 → 대안과 한계**를 남긴다.
- 항목을 추가할 때는 아이템 이름으로 새 폴더를 만들고 이 목록을 확장한다. 책의 아이템 번호는 목록과 문서 제목에서 관리한다. 폴더 이름을 바꾸면 연결된 링크도 함께 수정한다.
