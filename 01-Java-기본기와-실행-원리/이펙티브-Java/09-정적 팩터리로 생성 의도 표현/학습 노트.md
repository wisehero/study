# 정적 팩터리로 생성 의도 표현

학습일: 2026-09-11 · 학습 순서 09 · 아이템 1

## 핵심 결론

정적 팩터리 메서드는 객체를 반환하는 이름 있는 static 메서드다. 이름으로 생성 의도를 드러내고, 객체 생성·재사용·구현체 선택을 메서드 안에서 결정할 수 있다. 생성자를 무조건 없애라는 뜻은 아니다.

이 노트는 대화에서 학습한 핵심 장점과 주의점을 정리한 것으로 아이템 전체의 모든 세부사항을 다룬 요약은 아니다. 코드는 설명용이며 실습 구현과 실행 검증은 아직 하지 않았다.

## 이름으로 의도를 표현한다

```java
Product product = new Product("크림", 10000, true);
```

true의 의미는 생성자 선언을 찾아봐야 한다. 이름을 붙이면 호출부에 생성 의도가 드러난다.

```java
Product.ready("크림", 10000);
Product.onSale("크림", 10000);
```

판매 준비 상품과 판매 중 상품을 같은 매개변수 타입으로 만들더라도 메서드 이름으로 구분할 수 있다. 반면 생성자는 이름이 클래스명으로 고정되어 있어 같은 타입 조합으로 두 개를 선언할 수 없다. 매개변수 이름만 바꾸는 것으로도 구분되지 않는다.

```java
public static Product onSale(String name, int price) {
    return new Product(name, price, true);
}
```

위 코드는 Product 클래스 안에 넣는 설명용 조각이다. boolean은 의도 차이를 보여주기 위한 것으로, 상태가 여러 개라면 앞에서 배운 enum과 함께 설계할 수 있다. 이름이 명확해도 가격 등 입력 검증은 여전히 필요하다.

## 호출마다 새 객체를 만들 필요가 없다

생성자를 new로 호출하면 새 객체를 만든다. 정적 팩터리는 기존 객체를 반환할 수도 있다.

```java
Boolean value = Boolean.valueOf(true);
```

Boolean.valueOf는 기존 Boolean.TRUE 또는 Boolean.FALSE를 반환한다. Integer의 작은 정수 캐시도 객체 재사용과 연결되는 사례다.

재사용은 불필요한 생성을 줄일 수 있지만, 가변 객체를 공유하면 한 호출자의 변경이 다른 호출자에게 보일 수 있다. 팩터리를 쓴다는 사실만으로 불변성이나 안전한 공유가 보장되지는 않는다. 호출자가 매번 새로운 객체를 기대해도 되는지는 반환 계약으로 정한다.

## 반환 타입과 구현체를 분리할 수 있다

```java
public static List<String> emptyTags() {
    return List.of();
}
```

호출자는 List라는 인터페이스로 결과를 사용하고, 구체적인 구현체 선택은 팩터리 안에 둘 수 있다. 선언한 반환 타입과 호환되는 하위 타입을 반환할 수 있으므로 입력이나 환경에 따라 구현체를 달리하는 설계도 가능하다.

다만 구현체를 바꾸더라도 호출자에게 약속한 동작은 지켜야 한다. 위 예제의 결과는 수정 불가능한 빈 목록이다. 수정 가능 여부 등 반환 계약이 결과에 따라 달라지지 않도록 주의한다. 이는 2번의 빈 목록 학습과 연결된다.

## 선택할 때의 주의점

- 생성자를 모두 private으로 제한하면 일반적인 외부 하위 클래스가 호출할 생성자가 없어 상속할 수 없다. 상속을 허용할지, 객체를 조합해서 사용할지 함께 판단한다.
- 정적 팩터리는 이름이 고정되어 있지 않으므로 사용자가 생성 기능을 찾기 쉽도록 문서와 명명 관례를 활용한다.
- of, from, valueOf, create 같은 이름이 쓰이지만 언어 차원에서 의미를 강제하지는 않는다. 실제 입력·반환 계약을 문서화한다.
- 단순한 객체는 생성자만으로 충분할 수 있다. 이름, 재사용 또는 구현체 선택의 이점이 있는지 보고 선택한다.
- 정적 팩터리 자체가 입력 유효성이나 불변성을 보장하지 않는다.

## 남은 실습

기존 목표의 기획전 초안 생성과 데이터 복원을 생성자·이름 있는 메서드로 비교하거나, 대화의 판매 준비·판매 중 상품 예제로 생성 의도를 확인한다. 실습 시 사용할 사례를 정하고 짧은 코드와 테스트로 구성한다. 입력 검증과 생성 결과의 의미를 확인하며, 이번에는 실행하지 않았다.
