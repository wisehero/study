# 인터페이스 구현 교체 실습

검증일: 2026-09-14 · Java 21 toolchain · Gradle Wrapper · JUnit

## 목적과 읽는 순서

동일한 주문 서비스에 서로 다른 할인 정책을 전달하여, 호출하는 업무 코드를 바꾸지 않고 구현을 교체할 수 있음을 확인한다. `chapter12`는 책의 장 번호가 아닌 우리 학습 순서 12를 뜻한다.

1. [DiscountPolicy](../../../java-lab/src/main/java/dev/study/javalab/effectiveJava/chapter12/DiscountPolicy.java): 할인 금액을 반환하는 공통 계약이다.
2. [FixedDiscount](../../../java-lab/src/main/java/dev/study/javalab/effectiveJava/chapter12/FixedDiscount.java)와 [PercentDiscount](../../../java-lab/src/main/java/dev/study/javalab/effectiveJava/chapter12/PercentDiscount.java): 각각 1,000원 할인과 10% 할인을 구현한다.
3. [OrderService](../../../java-lab/src/main/java/dev/study/javalab/effectiveJava/chapter12/OrderService.java): 전달받은 정책으로 최종 가격을 계산한다.
4. [InterfaceExampleTest](../../../java-lab/src/test/java/dev/study/javalab/effectiveJava/chapter12/InterfaceExampleTest.java): 구현 교체와 공통 계약, 경계 결과를 확인한다.

## 구현을 교체하는 지점

```java
var fixedOrder = new OrderService(new FixedDiscount());
var percentOrder = new OrderService(new PercentDiscount());

fixedOrder.finalPrice(20000);   // 19000
percentOrder.finalPrice(20000); // 18000
```

인터페이스 A는 `DiscountPolicy`, 구현 B와 C는 `FixedDiscount`와 `PercentDiscount`에 해당한다. `OrderService`에는 구현 종류를 판별하는 분기가 없으며 최종 가격 계산 코드는 그대로다. 생성 시 전달하는 객체만 다르다. 이미 만든 주문 서비스의 정책을 setter로 교체하는 예제는 아니다.

두 구현은 비교 학습을 위해 함께 둔다. 실제 서비스에서 C로 이전한 후 B를 사용하지 않는다면 B와 전용 테스트를 삭제할 수 있다. 인터페이스의 이점은 B를 남기는 것이 아니라 호출자와 구현을 분리하는 데 있다. 이번 실습에서는 B 삭제를 수행하지 않았다.

## 계약과 검증 결과

`discount`는 최종 가격이 아닌 할인 금액을 반환한다. 두 구현 모두 음수 가격을 `IllegalArgumentException`으로 거절하고 할인 금액을 0 이상 상품 가격 이하로 유지한다. 주문 서비스는 이 계약에 의존한다. 임의의 새 구현이 계약을 어겨도 인터페이스 문법 자체가 막아주지는 않는다.

Java Lab에서 `./gradlew test`를 실행했다. 신규 3개를 포함한 전체 40개 테스트가 통과했고 실패·오류·건너뜀은 없었다.

- 같은 20,000원 상품의 최종 가격이 정액 정책에서는 19,000원, 정률 정책에서는 18,000원이다.
- 두 정책에 0·1·999·1,000·1,001·20,000·int 최댓값을 전달해 할인액 범위와 최종 가격 계산을 확인했다. 0원은 최종 가격도 0원이며 음수 가격은 두 정책 모두 거절한다.
- 정액 정책에서 500원 상품은 할인액을 500원으로 제한하여 최종 가격이 0원이다.
- 정률 정책에서 1,001원 상품은 100원을 할인하여 최종 가격이 901원이다. `price / 10`으로 10%를 계산해 정수 곱셈의 오버플로를 피하고 원 미만을 버린다.
- 정책 객체가 null이면 주문 서비스 생성자가 `NullPointerException`으로 거절한다.

## 실행과 후속 학습

Java Lab 디렉터리에서 실행한다. 별도 main 메서드는 추가하지 않았다.

```sh
./gradlew test --tests 'dev.study.javalab.effectiveJava.chapter12.*'
```

할인 금액과 비율은 구조를 짧게 유지하기 위해 고정했다. 정책 설정 객체, Spring 빈, DB는 도입하지 않았다. 직접 정액 할인값을 변경하여 어느 테스트 결과가 달라지는지 예상하고 실행해 보는 학습 확인이 남아 있다. 추상 클래스 방식의 비교와 11번 Clock 실습은 이번 구현 범위에 포함하지 않았다.
