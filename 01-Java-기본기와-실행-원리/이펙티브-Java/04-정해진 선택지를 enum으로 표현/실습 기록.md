# enum 실습 기록

검증일: 2026-09-11 · Java 21 toolchain · Gradle Wrapper · JUnit

## 읽는 순서

1. [ProductStatus](../../../java-lab/src/main/java/dev/study/javalab/effectiveJava/chapter04/ProductStatus.java): 허용된 상태, 전이 규칙과 외부 코드를 읽는다.
2. [Product](../../../java-lab/src/main/java/dev/study/javalab/effectiveJava/chapter04/Product.java): 같은 상태 요청 처리 → 전이 검증 → 대입 순서를 읽는다.
3. [EnumExampleTest](../../../java-lab/src/test/java/dev/study/javalab/effectiveJava/chapter04/EnumExampleTest.java): 세 테스트로 예상 결과를 확인한다.

## 실행과 결과

Java Lab에서 `./gradlew test`를 실행했다. 새 테스트 3개와 기존 20개, 총 23개가 통과했다.

- 정상 흐름: READY → ON_SALE → DISCONTINUED. 각 상태에서 같은 상태 재요청도 성공했다.
- 거절: READY → DISCONTINUED, ON_SALE → READY, DISCONTINUED → ON_SALE, null 입력. 예외가 발생하고 기존 상태는 유지됐다.
- 외부 코드: 각 상태의 code를 다시 읽으면 원래 상태가 된다. on_sale은 허용하며 ON_SALE, UNKNOWN, null은 거절한다.

## 핵심과 한계

enum은 선택지를 제한하고, 상품 메서드는 전이 규칙을 지킨다. code는 ordinal과 독립되어 선언 순서에 의존하지 않는다. 소스 두 파일과 짧은 테스트만으로 핵심을 확인하도록 별도 실행기나 저장소 구현은 추가하지 않았다.

DB·JSON 변환과 이벤트 중복 방지는 구현하지 않았다. 컴파일 불가능한 잘못된 타입의 호출은 학습 노트에서 설명하며 테스트 소스에 포함하지 않았다. 직접 코드를 변경하고 결과를 설명하는 학습 확인은 남아 있다.
