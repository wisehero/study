# 동등성과 해시 실습 기록

검증일: 2026-09-14 · Java 21 toolchain · Gradle Wrapper · JUnit

## 목적과 읽는 순서

[ProductCode](../../../java-lab/src/main/java/dev/study/javalab/collections/ProductCode.java)의 문자열 기준 equals·hashCode를 읽고 [HashExampleTest](../../../java-lab/src/test/java/dev/study/javalab/effectiveJava/chapter15/HashExampleTest.java)의 네 테스트를 순서대로 확인한다. 정상 타입과 문제 재현용 타입을 비교하여 정확성, 충돌, 키 변경을 구분한다.

| 테스트 | 확인한 결과 |
| --- | --- |
| 동등한 상품 코드 | 같은 해시값을 반환한다. HashSet에는 하나만 남고, 별도로 만든 같은 코드로 HashMap 조회·갱신이 가능하다. |
| 의도적으로 다른 해시값 | equals는 true여도 HashSet에 두 개가 남고 다른 객체를 키로 조회하면 null이다. |
| 상수 해시값 | P001과 P002는 서로 다른 원소로 저장되고 P001 중복은 제거된다. |
| 저장 후 키 변경 | P001을 P002로 바꾸면 해당 키로 집합·맵의 조회와 삭제가 실패하지만 순회에서는 같은 객체가 남아 있음을 확인할 수 있다. |

## 문제 재현용 타입

세 타입은 테스트 내부에만 둔다. 실제 예제의 불변 ProductCode에 잘못된 계약이나 변경 메서드를 추가하지 않는다.

- `BrokenHashCode`: equals는 문자열만 비교하지만 해시값은 생성자에서 받은 값을 반환한다. Object의 기본 해시값이 서로 다를 것이라고 가정하지 않고 1과 2를 지정해 실패를 재현한다. 이는 equals만 재정의하고 기본 hashCode를 사용하는 경우에 발생할 수 있는 불일치를 명시적으로 만든 예제다.
- `ConstantHashCode`: record의 값 동등성은 유지하며 hashCode만 항상 1을 반환한다. 해시 충돌이 있어도 중복 판정의 정확성이 유지됨을 확인한다.
- `MutableCode`: 변경 가능한 문자열로 equals와 hashCode를 계산한다. 집합과 맵에 넣은 후 필드를 변경해 조회 실패와 원소 잔류를 함께 확인한다.

가변 키 사례는 이번 Java 21 환경과 선택한 문자열로 확인한 결과다. 동등성에 영향을 주는 키 변경은 컬렉션의 안전한 사용법이 아니며, 임의의 키 변경이 항상 같은 실패 양상을 보인다는 일반 계약으로 해석하지 않는다. HashMap의 값 변경과도 구분한다.

## 실행과 검증

Java Lab 디렉터리에서 실행한다.

```sh
./gradlew test --tests 'dev.study.javalab.effectiveJava.chapter15.*'
```

`./gradlew test run`으로 14번 신규 3개와 이번 신규 4개를 포함한 전체 47개 테스트 및 기존 실행 예제를 검증했다. 실패·오류·건너뜀은 없었다.

상수 해시값 테스트는 정확성만 검증하며 성능 측정이 아니다. 분산 성능이나 특정 시간 복잡도를 측정 결과로 주장하지 않는다. 새 예제는 테스트로 실행하며 별도 main은 추가하지 않았다. 직접 해시 구현을 바꾸고 실패 이유를 설명하는 학습 확인은 남아 있다.
