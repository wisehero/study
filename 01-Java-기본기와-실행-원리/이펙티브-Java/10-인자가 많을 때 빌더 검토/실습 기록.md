# 빌더 실습 기록

검증일: 2026-09-11 · Java 21 toolchain · Gradle Wrapper · JUnit

## 코드와 읽는 순서

- [Product](../../../java-lab/src/main/java/dev/study/javalab/effectiveJava/chapter10/Product.java): Builder에 값을 모으고 build가 호출하는 private 생성자에서 검증 후 복사한다.
- [BuilderExampleTest](../../../java-lab/src/test/java/dev/study/javalab/effectiveJava/chapter10/BuilderExampleTest.java): 기본값, 잘못된 설정, 완성된 객체와 빌더의 분리를 확인한다.

```java
Product product = new Product.Builder("크림", 10000)
        .stock(100)
        .build();
```

필수 인자는 상품명과 가격이고 선택 인자는 재고다. 재고 생략은 0으로 정했다. 설정 중인 Builder에는 잘못된 값이 잠시 들어갈 수 있지만 build에서 거절한다. 완성된 Product는 final 필드와 읽기 메서드만 제공한다.

## 검증 결과

Java Lab에서 `./gradlew test`를 실행했다. 신규 3개와 이 브랜치의 기존 31개, 총 34개 테스트가 통과했다.

- 재고를 생략하면 0, 지정하면 지정한 값이 된다. 0원도 허용한다.
- null·빈 상품명·공백·음수 가격·음수 재고는 build 시 예외로 거절한다. 실패한 빌더의 재고를 수정하면 정상 생성할 수 있다.
- 같은 빌더의 재고를 10에서 20으로 바꾸어 다시 생성해도 먼저 만든 상품의 재고는 10으로 유지된다.

3번 테스트는 빌더와 결과 객체가 분리되어 있음을 보여준다. 이 예제는 String과 기본형만 사용하므로 가변 목록 공유 문제는 포함하지 않는다.

## 실행과 범위

```sh
./gradlew test --tests 'dev.study.javalab.effectiveJava.chapter10.*'
```

소스 한 파일과 테스트 한 파일로 구성했고 별도 main은 추가하지 않았다. 기존 기획전 목표 대신 대화의 상품 예제를 사용했다. 구조를 짧게 유지하려고 무료배송 옵션과 교차 필드 규칙은 생략했다. 실제 규칙이 여러 필드에 걸치면 최종 구성 전체를 검증해야 한다. 이 규모의 객체는 생성자로도 충분할 수 있으며, 빌더 구조를 설명하기 위한 예제다.

직접 코드 변경 후 결과를 설명하는 학습 확인과 교차 필드 검증은 후속 범위로 남긴다.
