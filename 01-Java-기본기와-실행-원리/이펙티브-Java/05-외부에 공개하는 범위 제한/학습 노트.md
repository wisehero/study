# 외부에 공개하는 범위 제한

학습일: 2026-09-11 · 학습 순서 05 · 아이템 15

## 핵심

클래스와 멤버는 실제 호출자가 필요한 만큼만 공개한다. 외부가 의존하는 부분을 줄이면 업무 규칙을 보호하고 내부 구현을 변경하기 쉬워진다. 내부 상태를 직접 다루지 못하도록 경계를 만드는 것을 캡슐화라고 한다.

```java
// public 필드라면 검증 메서드를 우회할 수 있다.
product.status = ProductStatus.DISCONTINUED;
```

필드는 private으로 숨기고 검증을 수행하는 도메인 메서드로 변경한다. 하지만 private 필드도 메서드가 가변 객체를 그대로 반환하면 노출될 수 있다. getTags().clear()가 내부 목록을 비우는 것이 그 예다.

## 접근 범위 선택

| 접근 제어자 | 범위 |
| --- | --- |
| private | 해당 선언을 감싸는 최상위 클래스 내부. 중첩 클래스도 포함 |
| 생략: package-private | 같은 패키지 |
| protected | 같은 패키지와 다른 패키지의 하위 클래스에서 제한적으로 접근 |
| public | 외부 공개. 해당 클래스와 패키지·모듈의 접근 가능 여부도 영향 |

일반 최상위 클래스에는 public 또는 package-private을 사용한다. shop.product와 shop.product.internal은 서로 다른 패키지다. 하위처럼 보이는 이름이 접근 권한을 주지는 않는다.

외부에서 필요한 changePrice는 public으로, 내부 검증 메서드는 private으로 둘 수 있다. 같은 패키지에서 공유할 보조 클래스는 package-private이 적합하다. 이번 예제의 PriceValidator는 이 접근 범위를 보여주기 위한 작은 보조 클래스다. 단일 클래스만 쓰는 검증이라면 Product의 private 메서드로 두는 편이 더 단순하다.

## 공개할 때 함께 확인할 점

- protected도 하위 클래스가 의존하는 약속이 되므로 확장에 필요한 부분만 공개한다.
- 테스트 때문에 public으로 넓히지 않는다. 같은 패키지의 테스트는 package-private에 접근할 수 있다. private 메서드는 보통 공개 동작을 통해 검증한다.
- public setter를 없앤 뒤에도 반환값을 통한 우회 변경을 확인한다.
- public static final List도 목록 내용까지 보호하지 않는다. final은 참조 재대입을 막을 뿐 add와 clear를 막지 못한다.

## 실습의 선택

Product는 가격과 태그를 private으로 보관한다. 생성자는 외부에서 유효한 상품을 만들기 위해 public으로 유지하고, 재사용하지 않는 PriceValidator 생성자는 private으로 막는다. 사용하지 않는 공개 기능을 추가하지 않는다.

태그는 List.copyOf로 수정 불가능한 스냅샷을 반환한다. 목록 복사는 원소 수에 비례하는 비용이 든다. 원소가 가변 객체라면 여전히 공유될 수 있지만, 이번 예제의 String은 불변이다. 스냅샷은 이후 내부 목록의 변경도 따라가지 않는다.
