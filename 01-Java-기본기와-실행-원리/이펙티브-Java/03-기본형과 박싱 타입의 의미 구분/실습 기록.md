# 기본형과 박싱 타입 실습 기록

검증일: 2026-09-11 · 학습 순서 03 · 아이템 61

## 목적과 구현

누락된 수량을 0으로 처리하거나 null을 자동 언박싱하면 잘못된 업무 처리 또는 예외가 발생한다. 요청 경계에서는 Long으로 누락 여부를 유지하고, 검증을 통과하면 long으로 전달하도록 구현했다.

- [StockRequest](../../../java-lab/src/main/java/dev/study/javalab/effectiveJava/chapter03/StockRequest.java): null과 음수를 거절하고 0 이상을 기본형으로 반환한다.
- [BoxingExample](../../../java-lab/src/main/java/dev/study/javalab/effectiveJava/chapter03/BoxingExample.java): 위험한 언박싱, 검증 후 합산, 참조·값 비교, 박싱·기본형 누적을 비교한다.
- [BoxingExampleTest](../../../java-lab/src/test/java/dev/study/javalab/effectiveJava/chapter03/BoxingExampleTest.java): 실패·경계 사례와 비교 규칙을 검증한다.

## 환경과 재현

Java 21 toolchain, Gradle Wrapper, JUnit을 사용했다. Java Lab에서 실행한다.

```sh
./gradlew test runEffectiveJava
# 3번 테스트만 실행할 경우
./gradlew test --tests 'dev.study.javalab.effectiveJava.chapter03.*'
```

BoxingExample.main을 IDE에서 실행하면 3번만 볼 수 있다.

## 예상과 실제 결과

| 사례 | 예상 결과 | 검증 결과 |
| --- | --- | --- |
| null을 0L과 비교 | 비교 전 언박싱에서 NullPointerException | 통과 |
| StockRequest의 null / -1L | IllegalArgumentException으로 거절 | 통과 |
| StockRequest의 0L / 1L | 각각 0 / 1 반환 | 통과 |
| 반복문의 null 원소 | 위험 예제는 언박싱 실패, 개선 예제는 누락 거절 | 통과 |
| 빈 수량 목록 / [1, 0, 3] | 합계 0 / 4 | 통과 |
| 합산 목록 자체가 null / 음수 원소 | 각각 NullPointerException / IllegalArgumentException | 통과 |
| Long.MAX_VALUE와 1 합산 | Math.addExact에서 ArithmeticException | 통과 |
| Integer 100의 박싱 객체 비교 | 같은 참조 | 통과 |
| Integer 1000의 equals / int 1000과 == | 둘 다 true | 통과 |
| Integer 1000과 Long 1000의 equals | false | 통과 |
| null에서 equals 호출 | NullPointerException | 통과 |
| Objects.equals(null, null) / (null, 0) | true / false | 통과 |
| 0~999의 박싱·기본형 누적 | 둘 다 499500 | 통과 |

3번 테스트 7개, 기존 테스트 13개를 포함해 총 20개가 통과했다. 실행 예제도 정상 종료했다. 이번 환경에서 Integer 1000의 참조 비교는 false였지만 캐시 범위 밖의 동일성을 고정된 결과로 테스트하지 않았다.

## 대안과 한계

- null을 0으로 대체하면 편리하지만 누락과 품절을 구분할 수 없다. 이번 예제는 필수 수량이므로 누락을 거절한다.
- Objects.equals는 null을 안전하게 비교하지만 두 미확인 값을 업무적으로 같다고 취급할지는 별도 판단이다. Integer와 Long의 값이 숫자로 같아도 equals는 false다.
- 박싱 합계와 기본형 합계는 결과를 비교했다. 실행 시간·메모리 측정은 하지 않았으며 JVM 최적화에 따른 실제 할당량을 단정하지 않는다.
- boxedTotal과 primitiveTotal은 0 이상 횟수로 합산하는 설명용 비교 메서드다. 업무 입력 검증 예제는 StockRequest와 sumRequiredQuantities다.
- Long 요청 필드는 순수 Java 객체로 모의했다. HTTP 요청에서 필드 누락을 역직렬화하는 과정은 Spring Lab 후속 범위다.

직접 예제를 변경하고 결과를 설명하는 학습 확인이 남아 있으므로 학습 상태는 검증 중으로 둔다.
