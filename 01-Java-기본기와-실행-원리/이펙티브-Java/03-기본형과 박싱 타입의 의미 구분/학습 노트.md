# 기본형과 박싱 타입의 의미 구분

학습일: 2026-09-11 · 학습 순서: 03/30 · 관련 항목: Effective Java 3판 아이템 61

## 핵심 결론

값 자체를 다루고 부재를 허용하지 않는다면 기본형을 우선 사용한다. 값의 부재를 표현하거나 제네릭에 사용해야 한다면 박싱 타입을 검토한다. 박싱 타입을 사용할 때는 null의 의미, 언박싱 시점, 값 비교 방법을 함께 정한다.

이 문서는 대화에서 학습한 개념을 정리한 것이다. 코드는 설명용이며, Java Lab에 3번 실습을 구현하거나 테스트를 실행한 결과는 아니다.

## 기본형과 박싱 타입

`int`와 `long`은 정수 값을 직접 다루는 기본형이다. `Integer`와 `Long`은 각각의 정수 값을 객체로 다루는 박싱 타입이다. 기본형에는 null을 담을 수 없지만 박싱 타입의 참조에는 null을 담을 수 있다.

재고를 예로 들면 0은 “재고가 없다는 사실을 알고 있음”, null은 “재고가 입력되지 않았거나 아직 확인되지 않음”을 뜻하도록 설계할 수 있다. 이때 null을 무조건 0으로 바꾸면 모르는 상태를 품절로 바꾸게 된다. null의 의미는 타입이 자동으로 정해 주는 것이 아니라 업무 계약으로 정해야 한다.

재고가 반드시 존재해야 한다면 int가 적합하다. 다만 int도 -1을 담을 수 있으므로 음수 금지는 입력 검증으로 별도 보장한다. 또한 객체의 int 필드는 기본값이 0이므로, int를 선택하는 것만으로 요청에서 값을 명시적으로 입력했는지 확인할 수는 없다. 입력 누락을 구분해야 한다면 요청 경계에서 박싱 타입 등으로 검증한 뒤 기본형으로 전달할 수 있다.

## 자동 언박싱은 조건 판단 전에 실패할 수 있다

박싱 객체에서 기본형 값을 자동으로 꺼내는 변환을 오토 언박싱이라고 한다.

```java
Integer stock = null;

if (stock == 0) {
    System.out.println("품절");
}
```

이 조건은 건너뛰어지는 것이 아니라 NullPointerException으로 실패한다. 오른쪽의 0이 int이므로 비교 전에 왼쪽에서 값을 꺼내야 한다. 아래와 같은 변환에서 null의 메서드를 호출하게 된다.

```java
if (stock.intValue() == 0) {
    System.out.println("품절");
}
```

null을 허용한다면 먼저 별도로 처리한다.

```java
if (stock == null) {
    System.out.println("재고 확인 필요");
} else if (stock == 0) {
    System.out.println("품절");
}
```

## 객체 동일성과 값 동등성

박싱 타입끼리의 `==`는 같은 객체를 가리키는지 비교한다. 같은 종류의 박싱 타입끼리 `equals()`를 사용하면 담긴 값을 비교한다. 반면 박싱 타입과 기본형을 `==`로 비교하면 언박싱 후 값을 비교한다.

```java
Integer a = 1000;
Integer b = 1000;

// a == b: 객체 동일성 비교. 값 비교 용도로 사용하지 않는다.
boolean sameValue = a.equals(b); // true
boolean equalToLiteral = a == 1000; // 언박싱 후 비교하므로 true
```

`a.equals(b)`는 a가 null이면 실패한다. null을 허용하는 비교에는 `java.util.Objects`의 `Objects.equals(a, b)`를 사용할 수 있다. 둘 다 null이면 true, 한쪽만 null이면 false, 둘 다 값이 있으면 equals로 비교한다. 다만 “둘 다 모르는 값”을 업무적으로 같은 것으로 취급해도 되는지는 별도로 판단해야 한다.

대화에서는 서로 다른 객체임을 확실히 보여 주려고 `new Integer(1000)` 두 개를 비교했다. 이 생성자는 사용 중단 대상으로 표시된 설명용 사례이며 새 코드에서는 사용하지 않는다. 실제 생성에는 오토 박싱이나 Integer.valueOf 등을 사용하고, 객체 재사용 여부와 관계없이 올바른 비교 방법을 선택한다.

## 작은 정수의 캐시가 비교 실수를 숨길 수 있다

```java
Integer a = 100;
Integer b = 100;

System.out.println(a == b); // true
```

위와 같은 작은 정수 상수의 박싱에서는 객체가 재사용된다. 정수 상수 -128~127의 박싱과 Integer.valueOf의 해당 범위는 객체 재사용이 보장된다. 범위 밖은 구현에 따라 재사용될 수 있으므로 1000의 박싱 객체가 반드시 서로 다르다고 가정해서도 안 된다.

따라서 100으로 테스트해서 ==가 true였다고 올바른 값 비교라고 판단하면 안 된다. 같은 타입의 정수 값 비교에는 equals 등을 사용한다.

## 제네릭과 반복문에서도 언박싱에 주의한다

제네릭은 사용할 타입을 인자로 받는 기능이다. List의 타입 인자에는 기본형을 사용할 수 없으므로 `List<int>` 대신 `List<Integer>`를 사용한다.

```java
List<Integer> numbers = Arrays.asList(1, null, 3);

for (int number : numbers) {
    System.out.println(number);
}
```

위 코드는 1을 출력한 뒤 null 원소를 int로 꺼내는 시점에 실패한다. 목록 자체가 null이 아니어도 원소가 null이면 언박싱 예외가 발생할 수 있다. 이 예제에는 java.util.List와 java.util.Arrays의 import가 필요하다.

## 계산 변수의 불필요한 박싱

```java
Long total = 0L;

for (int i = 0; i < 1000; i++) {
    total += i;
}
```

이 코드는 언박싱, 덧셈, 다시 박싱하는 변환을 반복한다. 합계에 부재 상태가 필요하지 않다면 `long total = 0L`로 선언할 수 있다. 박싱은 객체와 변환 비용을 늘릴 수 있지만 실제 할당이나 성능 영향은 실행 환경과 최적화에 따라 달라진다. 이 학습에서는 성능을 측정하지 않았다.

## 남은 실습

- Long 요청 필드에서 null과 0L의 의미를 구분하고, 입력 누락을 검증한다.
- null의 비교·계산·반복문 언박싱에서 예외가 발생하는 위치를 확인한다.
- ==, equals, Objects.equals의 결과를 비교한다. 캐시 범위 밖의 객체 동일성은 특정 결과로 단정하지 않는다.
- Java Lab에서 예상 결과와 실행 결과를 기록한 뒤, 필요한 경우 Spring Lab에서 요청 누락과 기본값 처리를 확인한다.
