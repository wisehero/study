# 객체 동등성 실습 기록

검증일: 2026-09-14 · Java 21 toolchain · Gradle Wrapper · JUnit

## 목적과 코드

기존 record가 자동 제공하던 값 비교를 일반 클래스에 직접 구현하여, 동일성과 동등성 및 equals의 계약을 확인한다. 별도 ProductCode를 복제하지 않고 기존 컬렉션 예제의 타입을 사용한다.

1. [ProductCode](../../../java-lab/src/main/java/dev/study/javalab/collections/ProductCode.java): final 일반 클래스로 전환하고 문자열 기준 equals와 hashCode를 구현했다. 기존 null·공백 검증과 `value()` 접근자, 출력 형식은 유지한다.
2. [EqualityExampleTest](../../../java-lab/src/test/java/dev/study/javalab/effectiveJava/chapter14/EqualityExampleTest.java): 동일성과 동등성, 다섯 규약과 잘못된 입력을 확인한다.
3. [CollectionExample](../../../java-lab/src/main/java/dev/study/javalab/collections/CollectionExample.java): 같은 상품 코드의 중복 제거와 최초 등장 순서 유지를 실행한다.

```java
var first = new ProductCode("P001");
var second = new ProductCode("P001");
```

두 인스턴스는 별개이지만 equals로는 동등하다. String 필드가 final이므로 생성 후 비교 기준이 바뀌지 않는다. 클래스의 final은 상속을 막는다. record에서 일반 클래스로 바뀌었으므로 record라는 타입 특성은 유지되지 않으며, 기존 예제에서 사용하는 공개 동작을 유지한 변경이다.

## 검증 결과

추가한 테스트 3개에서 다음을 확인했다.

- 같은 문자열을 가진 별도 객체를 사용해 반사성·대칭성·추이성을 확인했다. 반사성은 `first.equals(first)`를 직접 호출한다. 상태가 바뀌지 않는 반복 비교에서도 결과가 같다.
- 다른 코드, null, String 자체와는 동등하지 않다. String과 ProductCode는 양방향 비교 모두 false다.
- null은 NullPointerException, 빈 문자열·공백·탭은 IllegalArgumentException으로 거절한다.

Java Lab에서 `./gradlew test run`을 실행해 15번의 신규 4개를 포함한 전체 47개 테스트가 통과했다. 실행 예제에서도 CREAM·TONER·CREAM이 CREAM·TONER로 중복 제거되며 출력 형식과 순서가 유지됐다.

## 실행과 한계

Java Lab 디렉터리에서 실행한다.

```sh
./gradlew test --tests 'dev.study.javalab.effectiveJava.chapter14.*'
```

고른 사례에 대한 검증이며 모든 가능한 입력을 증명하는 것은 아니다. 일반 클래스의 equals를 제거하면 어떤 테스트가 실패할지 직접 예상하고 실행하는 학습 확인은 남아 있다. 영속성 엔티티와 상속을 허용한 값 객체의 비교는 포함하지 않는다.
