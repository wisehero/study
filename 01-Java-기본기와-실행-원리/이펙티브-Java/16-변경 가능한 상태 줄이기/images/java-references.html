목록을 복사해도, 원소 객체는 공유될 수 있다

사각형은 변수·객체, 화살표는 참조다. 세 경우를 비교하고 외부 Tag의 이름을 바꿔 보자.

참조 관점에서 코드 읽기
Java의 인자 전달은 값 전달이다. new Product(tags)에서는 객체 전체가 복제되는 것이 아니라 tags가 가진 참조 값이 매개변수로 복사된다. 목록의 원소도 참조 타입이면 그 객체를 가리키는 참조로 연결된다.
final은 필드의 재할당을 막는다. List.copyOf는 목록의 추가·삭제·교체를 막지만, 원소의 메서드 호출이나 필드 변경까지 막지 않는다. tags.get(0)은 해당 원소의 참조를 반환하므로 공유된 Tag의 변경이 양쪽에서 보인다.


String이면 괜찮은 이유 · 원소까지 복사할 때의 한계
String은 그 객체의 내용을 바꾸는 연산이 없다. 따라서 String 참조를 공유해도 괜찮다. 원본 목록에서 다른 String으로 교체하는 tags.set(0, "할인")은 L1의 칸을 바꾸는 것이며, List.copyOf로 만든 L2의 칸에는 영향을 주지 않는다.
가변 Tag를 새로 만들면 외부 원소와 분리된다. 하지만 getter로 내부 Tag를 그대로 돌려주면 호출자가 그 Tag를 바꿀 수 있다. 불변 Tag를 사용하거나 입력·출력 양쪽에서 필요한 복사를 해야 한다. 3번은 String 필드 하나인 Tag를 복사한 예제이며 임의의 객체 그래프를 재귀 복사하는 코드는 아니다.

ArrayList 입력을 전제로 그린 개념도다. List.copyOf는 이미 적합한 수정 불가능 목록을 받으면 재사용할 수 있다. JVM의 실제 저장 배치와 JIT 최적화는 생략했으며, 모든 참조가 스택에 있다는 뜻은 아니다. Product.tags는 객체 안의 필드다.
