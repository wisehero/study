# 공부 목표: 읽기 모델과 데이터 동기화

> 상태: 시작 전 · 작성일: 2026-09-09 · 상위 주제: 전시 도메인

## 학습 목적

상품 원본(쓰기 모델)의 변경을 전시 조회(읽기 모델)에 반영하는 방식을 설계하고, 두 모델을 분리하는 이유와 동기화 지연·유실·순서 역전을 다루는 방법을 설명한다.

## 핵심 개념별 목표

- [ ] 쓰기 모델과 읽기 모델의 분리는 상품 원본은 정규화된 형태로, 전시 조회는 화면에 맞게 비정규화된 형태로 따로 두는 것이다. 조회 성능과 원본 시스템 장애로부터의 격리가 목적이다.
- [ ] 동기화 방식은 조회 시점 직접 조회, 이벤트 기반 비동기 갱신, 배치 재계산으로 나뉜다. 각 방식의 반영 지연·정합성·구현 복잡도를 비교한다.
- [ ] 이벤트는 트랜잭션 커밋 이후에 발행한다. 커밋 전에 발행하면 실패한 변경의 이벤트가 나갈 수 있다.
- [ ] 이벤트 소비는 멱등해야 한다. 같은 이벤트가 중복 도착해도 읽기 모델이 같은 최종 상태가 되도록 처리한다.
- [ ] 이벤트 순서 역전과 유실은 읽기 모델이 오래된 상태로 남는 원인이다. 버전 번호나 타임스탬프로 오래된 이벤트를 무시하는 방법을 이해한다.
- [ ] 읽기 모델의 초기 적재와 재구성은 스키마 변경이나 장애 복구 시 필요하다. 서비스 중단 없이 재구성하면서 동시에 들어오는 실시간 이벤트와의 경합을 처리하는 방법을 이해한다.

## 초기 실습 정책

다음은 연습을 구체화하기 위해 선택한 정책이다. 실제 회사의 현재 동작이나 모든 쇼핑몰의 공통 규칙을 뜻하지 않는다. 정책을 바꾸면 이유와 영향받는 테스트를 함께 기록한다.

- 초기 실습은 상품 원본 DB의 트랜잭션 커밋 후 아웃박스 테이블에 이벤트를 함께 기록하고, 별도 프로세스가 이를 읽어 발행하는 방식으로 시작한다.
- 이벤트에는 상품 ID, 변경 유형, 버전 번호(또는 변경 시각)를 포함한다. 읽기 모델은 자신이 가진 버전보다 낮은 이벤트를 무시한다.
- 이벤트 소비자는 처리 완료 여부를 기록하고, 같은 이벤트 ID가 다시 도착하면 재처리 없이 완료로 응답한다.
- 재구성 배치는 원본을 페이지 단위로 순회하며 읽기 모델을 갱신한다. 재구성 중 도착한 이벤트는 별도로 쌓아두고 재구성 완료 후 순서대로 적용한다.

## 실습 과제

1. 로컬 아웃박스 또는 인메모리 큐로 상품 가격·판매 상태 변경 이벤트를 발행하고, 전시 읽기 모델에 반영하는 소비자를 만든다.
2. 같은 이벤트를 중복 전달해도 읽기 모델 값이 동일하게 유지되는지 검증한다.
3. 이벤트를 일부러 순서를 뒤바꿔 보내고, 오래된 이벤트가 최신 상태를 덮어쓰지 않는지 버전 검증으로 확인한다.
4. 읽기 모델을 삭제한 뒤 원본으로부터 전체 재구성하고, 재구성 도중 들어온 신규 이벤트와의 경합을 처리한다.

## 스스로 설명할 질문

- 상품 가격을 원본에서 바꿨는데 전시 화면에 반영되지 않는다면 어디부터 확인하는가?
- 이벤트 소비자가 다운되었다가 복구되었을 때 유실 없이 이어받으려면 무엇이 필요한가?
- 읽기 모델 재구성 중 들어온 실시간 이벤트를 즉시 적용하지 않는 이유는 무엇인가?

## 완료 기준

- [ ] 쓰기 모델과 읽기 모델을 분리하는 이유를 성능·격리 관점에서 설명한다.
- [ ] 이벤트 중복·순서 역전·유실 상황을 각각 재현하고 해결 근거를 남긴다.
- [ ] 읽기 모델 재구성 절차와 운영 중 안전성 확보 방법을 설명한다.
- [ ] 설계 이유, 실패 또는 경계 조건, 검증 결과를 학습 노트와 실습 기록에 남긴다.
