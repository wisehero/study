# 공부 목표: 전시 캐시·성능과 운영

> 상태: 시작 전 · 작성일: 2026-09-09 · 상위 주제: 전시 도메인

## 학습 목적

반복되는 전시 조회의 비용을 줄이면서 변경 반영 지연과 장애 시 노출 정책을 측정하고 통제한다.

## 핵심 개념별 목표

- [ ] 캐시는 조회 결과를 일정 기간 재사용하는 저장소다. 캐시 적중률은 요청 중 저장된 결과를 재사용한 비율이며, 빠른 응답이 최신 데이터임을 뜻하지는 않는다.
- [ ] TTL은 캐시 항목의 유효 기간이다. 데이터 변경 시 만료 전에 삭제하는 무효화와 함께 사용할 수 있다.
- [ ] 캐시 키는 서로 다른 응답을 구별하는 식별자다. 초기에는 화면·구역·페이지·필터·정렬·전시 버전을 고려하고, 국가·언어가 추가되면 그 차원도 반영한다.
- [ ] 동시 캐시 재생성은 인기 데이터가 만료된 순간 많은 요청이 DB나 외부 시스템으로 몰리는 현상이다.
- [ ] 변경 반영 지연은 관리자가 저장한 뒤 고객 조회에 보이기까지의 시간이다. 허용 범위를 정하고 평균 응답 시간과 별도로 관찰한다.

## 초기 실습 정책

다음은 연습을 구체화하기 위해 선택한 정책이다. 실제 회사의 현재 동작이나 모든 쇼핑몰의 공통 규칙을 뜻하지 않는다. 정책을 바꾸면 이유와 영향받는 테스트를 함께 기록한다.

- 캐시 없는 조회를 먼저 완성하고 측정한다. 캐시 도입 후에도 동일한 입력과 노출 정책을 기준으로 결과를 비교한다.
- 초기 실습은 고객 공개 조회만 캐시한다. 관리자 편집·미리보기 결과는 고객 캐시와 공유하지 않는다.
- 일반 순서·문구 변경은 실습 목표로 최대 30초의 반영 지연을 허용한다. 이 값은 업계 표준이 아닌 연습용 선택이며 실제 요구에 따라 조정한다.
- 예약 종료와 강제 비공개에는 일반 편집과 별도의 노출 차단 기준을 둔다. 캐시의 시각 정보와 현재 공개 상태를 재검증하고, 검증 실패 시 콘텐츠를 숨기거나 명시적 오류로 응답한다.
- DB 커밋 이후 캐시를 갱신·무효화한다. 늦게 끝난 이전 조회가 오래된 값을 다시 쓰는 경쟁 상태도 실험한다.
- 응답 시간 목표는 로컬 환경·데이터량·동시 요청 수를 기록한 뒤 설정한다. 근거 없는 운영 처리량을 목표로 삼지 않는다.

## 실습 과제

1. 캐시 적용 전후의 SQL 수, 지연시간 분포, 오류율, 캐시 적중률을 동일한 부하 조건에서 비교한다.
2. 기획전 수정과 조회를 겹치게 실행해 오래된 결과가 다시 저장되는 상황을 재현하고, 전시 버전 또는 재검증 방식으로 해결한다.
3. 종료 직전 생성된 캐시가 종료 이후 남아 있는 상황과 강제 비공개 직후의 요청을 검증한다. 신규 응답과 이미 사용자에게 전달된 화면의 보장 범위를 구분한다.
4. 인기 구역의 캐시를 동시에 만료시키고 DB 요청 급증을 관찰한다. 재생성 동시성 제한 등 대응을 적용해 비교한다.
5. 캐시 장애와 원본 조회 장애를 각각 재현한다. 부하 한도 내 원본 조회, 제한된 이전 결과 사용, 명시적 오류 중 허용 정책을 정하고 비공개 콘텐츠에는 별도 기준을 적용한다.

## 스스로 설명할 질문

- 캐시 TTL이 30초면 관리자의 모든 변경이 항상 30초 이내에 반영되는가?
- 트랜잭션 커밋 전에 캐시를 삭제하면 어떤 경쟁 상태가 생길 수 있는가?
- 예약 종료 직전 캐시한 기획전이 종료 후에도 보이지 않도록 어떻게 검증하는가?
- 캐시 적중률이 높아도 고객에게 잘못된 결과를 줄 수 있는 이유는 무엇인가?

## 완료 기준

- [ ] 캐시 키, 만료, 변경 반영, 장애 시 정책을 문서로 정의한다.
- [ ] 동시 수정과 오래된 캐시 재저장 문제를 재현하고 해결 근거를 남긴다.
- [ ] 기간 종료·강제 비공개·미리보기의 노출 정책이 캐시에서도 유지됨을 검증한다.
- [ ] 성능 효과와 변경 반영 지연을 같은 실험에서 측정한다.
- [ ] 설계 이유, 실패 또는 경계 조건, 검증 결과를 학습 노트와 실습 기록에 남긴다.
