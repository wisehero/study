# 공부 목표: 기획전·배너와 노출 정책

> 상태: 시작 전 · 작성일: 2026-09-09 · 상위 주제: 쇼핑몰 상품 전시

## 학습 목적

운영자가 편집하는 콘텐츠와 고객이 볼 수 있는 콘텐츠를 구분하고, 공개 상태·시간·접근 경로에 따라 일관된 전시 결과를 제공한다.

## 핵심 개념별 목표

- [ ] 기획전은 특정 목적에 따라 상품과 콘텐츠를 모은 화면이다. 전시 구역은 화면 안의 배너·상품 목록 같은 배치 단위다.
- [ ] 배너는 이미지·대체 텍스트·연결 대상을 가진 콘텐츠다. 연결 대상의 존재 여부와 공개 여부를 표시 조건과 함께 판단한다.
- [ ] 공개 승인은 운영자의 의사결정이며, 현재 노출 가능 여부는 승인·기간·연결 데이터 등을 함께 계산한 결과다.
- [ ] 미리보기는 아직 고객에게 공개하지 않은 편집 내용을 확인하는 관리 기능이다. 고객 조회와 접근 권한 및 캐시를 분리한다.

## 초기 실습 정책

다음은 연습을 구체화하기 위해 선택한 정책이다. 실제 회사의 현재 동작이나 모든 쇼핑몰의 공통 규칙을 뜻하지 않는다. 정책을 바꾸면 이유와 영향받는 테스트를 함께 기록한다.

- 초기 실습의 저장 상태는 DRAFT(초안), PUBLISHED(공개 승인), SUSPENDED(노출 중지)로 둔다. 예약 대기·진행·종료는 공개 승인 상태와 현재 시각을 조합해 계산한다.
- 노출 시간은 시작 시각 이상, 종료 시각 미만인 구간으로 정한다. 시작과 종료가 같거나 순서가 뒤집힌 설정은 거절한다.
- 관리자가 입력한 시간대 정보를 명시하고 비교 가능한 시점으로 변환한다. 테스트에서는 현재 시각을 주입하여 경계를 재현한다.
- 미리보기는 권한이 있는 관리자만 조회한다. 고객 API에서는 미리보기용 매개변수만으로 비공개 콘텐츠를 열 수 없다.
- 배너는 공개된 내부 기획전 또는 상품을 연결 대상으로 사용한다. 연결 대상 삭제·비공개 시 배너를 숨기며, 만료된 고객 기획전 URL은 찾을 수 없음으로 응답한다.

## 실습 과제

1. 기획전 생성 → 구역·배너 편집 → 미리보기 → 공개 승인 → 기간 시작 → 종료의 흐름과 응답 예시를 작성한다.
2. 시작 직전·시작 시각·종료 직전·종료 시각의 노출 여부를 고정된 시계로 검증한다.
3. 관리자 미리보기 URL을 일반 고객과 비로그인 사용자가 호출하는 권한 테스트를 작성한다.
4. 공개 중인 기획전의 배너 대상이 삭제되거나 비공개가 되는 경우와 모든 구역이 비는 경우의 응답을 정의한다.

## 스스로 설명할 질문

- 예약 공개에 배치 작업이 반드시 필요한가? 요청 시각으로 계산하는 방식과 어떤 차이가 있는가?
- 상태가 PUBLISHED라면 항상 고객에게 보여도 되는가?
- 미리보기 응답이 고객용 캐시에 저장되지 않도록 무엇을 구분해야 하는가?

## 완료 기준

- [ ] 저장 상태와 계산된 노출 상태를 구분한 상태·시간 표를 작성한다.
- [ ] 시간 경계, 비공개 직접 접근, 끊어진 배너 연결을 검증한다.
- [ ] 시간대와 빈 화면의 처리 정책을 문서로 남긴다.
- [ ] 설계 이유, 실패 또는 경계 조건, 검증 결과를 학습 노트와 실습 기록에 남긴다.
