# 공부 목표: 쇼핑몰 상품 전시 도메인

> 상태: 시작 전 · 작성일: 2026-09-09 · 실습 도메인: 카테고리·기획전·배너·상품 진열

## 학습 목적

쇼핑몰 운영자가 상품과 콘텐츠를 배치하고, 고객이 공개 조건에 맞는 화면을 조회하는 전시 기능을 설계한다. Java·Spring 기초 지식을 데이터 모델, 시간·공개 정책, 동시 편집, 조회 성능과 캐시 문제에 적용하는 것이 목표다.

전시 도메인은 상품을 어떤 화면에 어떤 순서와 조건으로 보여줄지 담당한다. 상품 원본의 가격·판매 상태, 재고와 주문 처리는 별도의 책임으로 구분한다. 처음에는 하나의 Spring 애플리케이션 안에서 책임을 나눠 구현하고, 서비스 분리는 후속 과제로 둔다.

이 문서는 앞으로 수행할 실습의 목표다. 아직 구현하거나 검증한 동작을 의미하지 않는다.

## 전체 흐름

1. 운영자가 카테고리를 구성하고 상품을 연결한다.
2. 운영자가 기획전 안에 구역을 만들고 배너와 상품을 배치한다.
3. 운영자가 순서와 노출 기간을 설정하고 권한이 있는 미리보기로 확인한다.
4. 공개 승인이 된 콘텐츠를 기간·공개 상태·상품 정책에 맞춰 고객에게 제공한다.
5. 변경과 종료가 발생하면 조회 및 캐시에 반영하고, 응답 성능과 반영 지연을 관찰한다.

## 범위와 선행 지식

- **초기 범위:** 하나의 쇼핑몰, 수동 진열, 카테고리 트리, 기획전·구역·배너, 노출 기간, 관리자 미리보기, 고객 목록 조회, 캐시 적용 전후 비교다.
- **선행 지식:** 기본적인 Java 객체·컬렉션, Spring 요청 처리, 관계형 DB의 조회·제약, 트랜잭션과 테스트다. 부족한 부분은 관련 기초 주제와 병행한다.
- **후속 확장:** 국가·언어·통화별 전시, 조건 기반 자동 진열, 개인화 추천, 검색 연동, 운영 변경 이력과 승인 절차, 상품 이벤트를 통한 조회 데이터 갱신이다.
- **환경:** Java·Spring Boot·DB 버전은 실습 시작 시 기록한다. 캐시 기술은 기본 조회 측정 이후 선택한다.

## 공통 실습 시나리오

가상의 ‘가을 스킨케어 기획전’을 만든다. 공개 상품, 품절 상품, 비공개 상품을 섞고 배너와 두 개의 상품 구역을 배치한다. 이 예시는 학습을 위한 가상 정책이며 실제 업무의 정책은 별도로 확인해야 한다.

- [ ] 카테고리에서 상품을 탐색하고 기획전 구역에 수동 배치한다.
- [ ] 관리자 두 명이 동시에 순서를 변경해도 한쪽 수정이 조용히 덮어써지지 않도록 한다.
- [ ] 시작·종료 시각 경계에서 노출 여부를 검증한다.
- [ ] 품절 상품은 표시하고, 비공개·판매 중지·삭제 상품은 숨긴다.
- [ ] 관리자 미리보기와 고객 조회의 접근 권한을 구분한다.
- [ ] 정렬 동률, 빈 구역, 끊어진 배너 연결, 페이지 사이의 편집을 검증한다.
- [ ] SQL과 실행 계획을 분석한 다음 캐시를 추가하고 성능 및 변경 반영 지연을 측정한다.
- [ ] 기간 종료·강제 비공개와 캐시의 관계를 검증한다.

주문·재고 실습과 연결할 경우 전시 화면의 가격·재고 정보만으로 주문을 확정하지 않는다. 주문 시점에는 주문 영역에서 다시 검증한다.

## 완료 기준과 남길 결과물

- [ ] **모델과 정책:** 상품 원본, 카테고리, 전시 배치의 책임 및 노출 규칙을 설명한다.
- [ ] **API와 예시:** 관리자 편집·미리보기와 고객 조회의 정상·오류 응답을 작성한다.
- [ ] **정합성:** 동시 순서 변경, 계층 순환, 시간 경계와 권한을 테스트로 검증한다.
- [ ] **측정:** 조회 최적화와 캐시 적용 전후의 SQL 수, 지연시간, 변경 반영 지연을 기록한다.
- [ ] **운영 판단:** 원본·캐시 장애와 강제 비공개 시의 행동 및 보장 한계를 설명한다.
