# 공부 목표: Spring 요청 처리와 프록시

> 상태: 시작 전 · 작성일: 2026-09-09 · 목표 수준: Java·Spring 미들급 개발자의 독립적인 구현·검증·문제 해결

## 학습 목적

HTTP 요청이 애플리케이션을 통과하는 경로와 Spring이 객체에 부가 기능을 적용하는 원리를 이해하여 설정 및 어노테이션 문제를 추적한다.

**학습 우선순위:** 트랜잭션 학습 전에 기본 흐름을 익힌다.

## 학습 환경

- Java / Spring Boot 버전: 미정
- DB / 데이터 접근 기술: 미정
- 실습 코드 위치: 미정

현재 프로젝트의 기술과 버전을 적은 뒤 시작한다. 확인하지 않은 동작은 가정으로 표시하고 실습으로 검증한다.

## 실습 프로젝트

[Spring Lab](../spring-lab/README.md)의 상품 API를 출발점으로 요청·빈·프록시 흐름을 추적한다. 순수 Java의 객체·스레드 실험은 [Java Lab](../java-lab/README.md)에서 독립적으로 진행한다.

## 핵심 개념별 목표

- [ ] **의존성 주입과 빈**: 의존성 주입은 필요한 객체를 외부에서 연결하는 방식이며, 빈은 Spring이 관리하는 객체다. 생성자 주입, 생명주기, 객체 범위를 이해한다.
- [ ] **싱글턴과 상태**: Spring 싱글턴은 컨테이너 안에서 공유되는 객체임을 이해한다. 공유 객체가 자동으로 스레드 안전해지는 것은 아님을 설명한다.
- [ ] **요청 처리 흐름**: 필터, 요청을 컨트롤러에 전달하는 DispatcherServlet, 인터셉터, 컨트롤러, 서비스의 역할과 실행 순서를 추적한다.
- [ ] **입력과 오류 처리**: 요청 값 바인딩, 유효성 검증, JSON 변환, 공통 예외 처리의 위치를 구분한다. 필터에서 발생한 예외와 컨트롤러 예외의 처리 경로 차이를 확인한다.
- [ ] **AOP와 프록시**: AOP는 여러 기능에 공통 처리를 적용하는 방식이며, 프록시는 실제 객체 호출을 중계하는 객체다. 호출이 프록시를 통과하는 조건을 설명한다.
- [ ] **설정과 자동 설정**: 컴포넌트 탐색, 프로파일, 외부 설정, 조건부 자동 설정을 이해하고 실제 적용된 빈과 설정을 확인한다.

## 실습 과제

1. 하나의 API에 필터·인터셉터·컨트롤러·서비스 로그를 추가하고 정상 요청과 검증 실패 요청의 경로를 비교한다.
2. 프록시를 거치는 외부 호출과 같은 객체 내부 호출을 비교하여 트랜잭션 적용 여부를 관찰한다. 내부 호출 전부터 트랜잭션이 존재하는 경우도 별도로 확인한다.
3. 하나의 자동 설정 조건을 바꾸고 어떤 빈이 생성되는지 설정 진단 결과로 확인한다.

## 스스로 설명할 질문

- 같은 클래스 내부 호출에서 @Transactional의 설정이 적용되지 않을 수 있는 이유는 무엇인가?
- 인증 검사, 요청 로깅, 업무 검증을 각각 어디에 두며 그 이유는 무엇인가?
- 직접 선언한 빈이 자동 설정에 어떤 영향을 주었는지 어떻게 확인하는가?

## 완료 기준

- [ ] 요청부터 응답까지 실제 코드와 실행 로그로 설명한다.
- [ ] 기본 프록시 방식에서 내부 호출과 외부 호출의 차이를 재현한다.
- [ ] 설정 문제 발생 시 적용 조건과 생성된 빈을 근거로 원인을 좁힌다.
- [ ] 실패 또는 경계 조건을 최소 하나 직접 재현하고 결과를 기록한다.
- [ ] 선택한 방법과 대안의 비용을 비교하고 코드·테스트·로그 등 검증 근거를 연결한다.

개념 체크는 자신의 말로 설명하고 예제에서 확인했을 때 표시한다. 문서나 강의를 읽은 것만으로 완료 처리하지 않는다.
