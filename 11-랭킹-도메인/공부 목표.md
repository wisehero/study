# 공부 목표: 상품 랭킹 도메인

> 상태: 시작 전 · 작성일: 2026-09-09 · 실습 도메인: 인기 상품·카테고리별 베스트

## 학습 목적

상품의 인기를 어떤 신호와 기간으로 계산할지 정의하고, 중복·취소·지연 데이터가 들어와도 설명 가능한 순위를 제공한다. 집계의 정확성, 순위 조회 성능, 결과의 최신성과 재현 가능성을 함께 검증한다.

전시가 상품을 배치하는 화면과 공개 규칙을 담당한다면, 랭킹은 정해진 기준으로 후보 상품의 순서를 계산한다. 검색에서는 검색어와의 관련도가 별도로 필요하므로 인기 순위를 검색 관련도와 동일하게 취급하지 않는다.

이 문서는 학습 목표와 실습용 정책이다. 실제 회사의 랭킹 공식이나 검증된 구현을 뜻하지 않는다.

## 전체 흐름

1. 구매·조회·찜 등 후보 신호를 비교하고 초기 집계 기준을 선택한다.
2. 기준 시점과 집계 기간을 고정해 원본 데이터에서 상품별 점수를 계산한다.
3. 공개 가능한 상품을 대상으로 점수와 동점 규칙에 따라 순위를 생성한다.
4. 생성이 완료된 집계 버전을 공개하고 전시 화면에서 순위를 조회한다.
5. 취소·정정·늦게 도착한 데이터의 반영 결과를 원본 재집계와 대조한다.

## 핵심 개념별 목표

- [ ] **순위 기준:** 판매 수량·주문 건수·매출·조회 수·찜 수의 의미와 왜곡 가능성을 구분한다. 여러 신호를 합산할 때 단위와 가중치의 근거를 설명한다.
- [ ] **기간과 기준 시각:** 자정 기준 일간 집계와 최근 24시간 집계를 구분한다. 사건 발생 시각과 시스템 수신 시각이 다를 때 어느 시각에 귀속할지 정의한다.
- [ ] **중복과 정정:** 같은 사건을 반복 처리해도 효과가 중복되지 않도록 식별자를 사용한다. 취소·부분 취소·늦은 도착·순서 역전의 반영 규칙을 설명한다.
- [ ] **전체 재집계와 증분 집계:** 원본에서 다시 계산하는 방식과 변경분만 반영하는 방식을 비교한다. 단순 누적 점수만으로 이동 시간창에서 오래된 기여가 자동 제거되지는 않음을 설명한다.
- [ ] **동점과 순위 표시:** 동일 점수에 공동 순위를 부여할지, 표시 위치만 구분할지 정한다. SQL의 RANK·DENSE_RANK·ROW_NUMBER가 어떤 결과 차이를 만드는지 예제로 확인한다.
- [ ] **집계 버전과 공개:** 계산 중인 결과를 고객에게 섞어 보여주지 않도록 완료된 결과 묶음을 공개한다. 페이지 이동 중 버전 변경의 영향을 다룬다.
- [ ] **조회 저장 구조:** SQL 집계·집계 테이블과 점수순 조회를 지원하는 Redis Sorted Set을 비교한다. 저장 구조가 중복 처리·취소·기간 정책까지 대신 해결하지는 않음을 구분한다.
- [ ] **품질과 운영:** 집계 지연, 원본 대비 점수 오차, 처리 실패, 재집계 시간, 조회 지연을 관찰한다. 반복 조회나 비정상 구매가 순위에 미칠 영향을 설명한다.

## 초기 실습 정책

다음은 계산 결과를 검증하기 위해 선택한 예시다. 기준을 바꾸면 변경 이유와 기대 순위를 함께 수정한다.

- 최초 점수는 **최근 24시간 결제 완료 상품 수량에서 기준 시점까지 확정된 취소 수량을 제외한 순수량**으로 한다. 결제 시각이 집계 기간에 속하는 주문 항목만 대상으로 삼는다.
- 기준 시점 T에 대해 기간은 `[T-24시간, T)`로 정한다. 취소는 원래 주문 항목의 기여를 줄이며 취소 수량은 원래 결제 수량을 초과할 수 없다. 환불만 된 금액 정산은 후속 과제로 둔다.
- 초기에는 5분마다 전체 재집계한다. 이는 연습용 주기다. 사건 시각의 조건과 DB의 일관된 읽기 시점을 함께 기록하고, 집계가 못 본 지연 데이터는 다음 버전에 반영한다.
- 점수가 양수인 공개·판매 중 상품을 점수 내림차순, 상품 ID 오름차순으로 정렬한다. 초기 순위 표시는 공동 순위 없이 1부터 시작하는 표시 위치로 정한다.
- 품절 상품은 품절 표시와 함께 유지한다. 비공개·판매 중지·삭제 상품은 고객 응답 전에 최신 공개 상태로 걸러내며, 상태 확인 실패 시 명시적 오류를 반환한다.
- 고객에게 보이는 순위는 집계 버전의 표시 위치를 유지하므로 숨겨진 상품의 순번이 비어 있을 수 있다. 페이지 크기보다 적게 반환되는 경우도 명시한다. 숨김 후 재번호 부여는 후속 정책 비교 과제로 둔다.
- 집계 버전에는 기준 시점·기간·정책 버전·완료 시각을 남긴다. 카테고리별 랭킹은 집계 시점의 소속을 기준으로 하며, 하나의 상품이 여러 카테고리에 포함될 수 있다.
- 계산 중 실패하면 기존 완료 버전을 유지한다. 이전 결과를 얼마나 오래 허용할지 정하고, 허용 시간을 넘으면 오래된 순위임을 표시하거나 오류로 응답하는 정책을 선택한다.

## 단계별 실습

1. 작은 결제·취소 데이터셋을 만들고 예상 점수와 동점 순서를 손으로 계산한다. 동일 입력·기준 시점·정책이면 같은 결과가 나오는지 검증한다.
2. SQL로 전체 및 카테고리별 랭킹을 만든다. 기간 시작·종료 경계, 부분 취소, 점수 0, 카테고리 이동을 검증한다.
3. 같은 집계의 동시 실행과 계산 중 실패를 재현하고, 일부 결과나 늦게 완료된 이전 버전이 최신 결과를 덮어쓰지 않도록 한다.
4. 전시 화면에 ‘최근 24시간 베스트’ 구역을 연결한다. 비공개 변경과 페이지 이동 중 집계 교체의 응답을 기록한다.
5. 후속 단계로 증분 집계를 구현한다. 사건 중복, 취소가 먼저 도착하는 상황, 오래된 기여의 기간 이탈을 재현하고 전체 재집계 결과와 대조한다.
6. 필요하면 Redis Sorted Set을 비교 실험한다. 동점 순서가 업무 규칙과 일치하는지 확인하고, 동일 데이터량에서 조회 지연·갱신 비용·재생성 시간을 측정한다.

## 스스로 설명할 질문

- 결제 시각은 어제인데 취소는 오늘 발생했다면 어느 점수에 영향을 주는가?
- 중복 사건을 막는 것만으로 순서가 뒤집힌 취소와 결제가 올바르게 처리되는가?
- Redis 점수를 계속 증가시키는 것만으로 최근 24시간 랭킹을 만들 수 있는가?
- 5분 주기 집계가 모든 변경의 5분 이내 반영을 보장하는가?
- 인기 점수가 높은 상품이 모든 검색어에서 상위에 나오는 것이 적절한가?

## 완료 기준

- [ ] 점수 공식·기간·취소·동점·노출 규칙을 설명하고 예상 결과표를 작성한다.
- [ ] 중복·정정·경계 시각에 대한 결과를 재현 가능한 데이터로 검증한다.
- [ ] 집계의 동시 실행과 실패 중에도 완료된 버전의 일관성이 유지된다.
- [ ] 전시 화면에서 순위, 기준 시각, 비공개 상품 제외가 정의한 정책대로 동작한다.
- [ ] 전체 재집계와 증분 또는 다른 조회 저장 구조의 비용을 측정하여 비교한다.
