# Redis 기초 공부 목표

> 상태: 학습 중 · 작성일: 2026-09-30

## 학습 목적

Redis가 데이터를 저장하고 처리하는 방식을 이해하고, 상품 조회 캐시에 적용할 때 얻는 이점과 데이터 갱신의 한계를 설명한다. 회사 ElastiCache의 Redis OSS 사용 여부는 아직 추정이므로 엔진과 버전을 확인한 뒤 실제 환경과 연결한다.

## 범위와 선행 지식

- 이번 범위: 메모리 기반 저장, 키와 기본 자료구조, Cache Aside, TTL과 축출, 명령의 원자성, 영속화와 복제의 목적.
- 후속 범위: Spring 연동, 동시 캐시 미스, 캐시 무효화 경쟁, Sorted Set 랭킹, 클러스터·장애 전환, ElastiCache 운영 설정.
- 선행 지식: 앱과 DB의 구분, Java 컬렉션, 상품 조회 API의 흐름.
- Redis 버전: 아직 확인하지 않음. 최신 문서의 기능과 회사 Redis OSS의 지원 기능을 구분한다.

## 핵심 개념별 목표

- [ ] Redis와 앱 내부 메모리, 관계형 DB, ElastiCache의 역할을 구분한다.
- [ ] String·Hash·List·Set·Sorted Set의 형태와 사용 예를 설명한다.
- [ ] 캐시 적중과 미스에서 앱·Redis·DB가 하는 일을 설명한다.
- [ ] TTL과 축출을 구분하고, TTL만으로 최신 데이터가 보장되지 않는 이유를 설명한다.
- [ ] `INCR`과 `GET → 증가 → SET`의 동시 요청 결과를 비교한다.
- [ ] 영속화와 복제를 구분하고 데이터 종류에 따라 유실 영향을 설명한다.

## 후속 실습 과제

1. 로컬 Redis에서 `SET`, `GET`, `TTL`을 실행하고 만료 전후의 결과를 확인한다.
2. 만료가 설정된 키를 일반 `SET`으로 덮어쓴 뒤 TTL의 변화를 확인한다.
3. 동시에 증가 요청을 보내 `INCR`과 여러 명령을 조합한 방식의 차이를 확인한다.
4. 상품 조회에 Cache Aside를 적용하고 캐시 미스·적중·DB 가격 변경 이후의 응답을 비교한다.

현재는 개념 정리 단계이며 실습 환경과 코드는 아직 추가하지 않았다.

## 스스로 설명할 질문

- 여러 앱이 Redis를 함께 사용하는 이유는 무엇인가?
- 캐시에 값이 없을 때와 Redis 접속 자체가 실패했을 때는 어떻게 다른가?
- 캐시를 지우고 다시 만드는 비용과 오래된 값을 보여주는 영향은 어떻게 비교할 수 있는가?
