# 초기 스캐폴딩 검증 기록

검증일: 2026-09-09

## 결과

- Java 21.0.10 / Spring Boot 4.1.1 / Gradle 9.7.1로 빌드했다.
- PostgreSQL 17.6 Testcontainers 통합 테스트 9개가 통과했다. 실패·오류·건너뜀은 모두 0개다.
- `bootJar`로 실행 파일을 생성했다.
- 테스트한 원본과 데스크톱으로 복사한 소스 파일의 내용 일치를 확인했다.
- 데스크톱의 앱 폴더에서 `docker compose up -d --wait`와 `./gradlew --no-daemon bootRun`으로 실행했다.
- local 프로파일에서 Flyway 기본 테이블과 샘플 데이터 마이그레이션이 적용되는 것을 확인했다.
- 실제 HTTP 요청으로 상태 확인, 관리자 인증, CSRF 토큰과 세션 쿠키, 상품 생성·공개 조회, 중복 409, 입력 오류 400을 확인했다.
- 문서의 내부 링크와 Gradle 실행 파일 권한을 확인했다.

## 통합 테스트 범위

1. 상품 저장의 커밋과 공개 상품 목록 필터링
2. 중복 상품 코드 충돌과 추가 행 미저장
3. 초안 상품의 알려진 ID로 직접 조회할 때 노출 차단
4. 잘못된 본문의 저장 전 검증
5. 잘못된 JSON과 상품 ID의 오류 응답
6. 페이지 번호·크기 범위 검증
7. 상품 생성의 인증과 관리자 권한
8. 관리자 변경 요청의 CSRF 보호
9. 공개 상태 확인과 관리자용 지표 접근

## 검증 후 상태

실행 확인용 상품 한 건을 제거했다. 기본 샘플 상품 3개는 로컬 DB 볼륨에 유지했고, 앱 프로세스와 Compose 컨테이너는 종료했다. 다시 실행하면 보존된 데이터를 사용한다.

기존 학습 문서의 미커밋 변경은 유지했다. 앱과 목록 연결도 커밋하지 않은 상태다.

이 기록은 초기 기반 기능에 대한 검증이다. 주문·재고·전시·랭킹·검색의 업무 기능과 성능은 해당 실습을 구현한 뒤 별도로 검증한다.

## Java·Spring 프로젝트 분리 후 검증

- 2026-09-09: 기존 `app`을 `spring-lab`으로 이동하고 `java-lab`을 독립 Gradle 프로젝트로 추가했다.
- Java 예제 실행과 JUnit 테스트 3개가 통과했으며 실행 의존성 목록은 비어 있음을 확인했다. 저장된 Java 소스가 검증한 원본과 일치함을 확인했다.
- 이동된 `spring-lab`에서 PostgreSQL 통합 테스트 9개와 `bootJar`가 통과했다.
- 전체 문서의 상대 링크와 새 프로젝트 경로를 확인했다.
- Spring의 Compose 프로젝트 이름과 데이터 볼륨 설정을 유지했다. Java 빌드는 Docker나 Spring을 실행하지 않는다.
