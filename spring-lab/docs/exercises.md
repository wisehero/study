# 실습 순서와 공부 목표 연결

실습은 현재 동작을 관찰하고, 작은 변경을 구현하고, 실패를 재현한 뒤 결과를 기록하는 순서로 진행한다. 아래 항목은 아직 완료되지 않은 학습 과제다.

## 1. 상품 예제로 요청과 저장 흐름 확인

- 시작 위치: `catalog/api`, `catalog/application`, `catalog/domain`, `catalog/infrastructure`
- 할 일: 상품 등록부터 SQL 실행까지 추적한다. 입력 검증과 도메인 검증, DB 제약이 맡는 역할을 구분한다.
- 확장: 상품 수정 API와 읽은 버전을 전달하는 계약을 설계하고 동시 수정 충돌을 검증한다.
- 연결: [Spring](../../02-Spring-요청-처리와-프록시/공부%20목표.md), [API 설계](../../09-API-설계-원칙/공부%20목표.md), [테스트](../../06-테스트와-변경하기-쉬운-설계/공부%20목표.md)

## 2. 주문과 재고

- 첫 실습: [커밋·롤백 학습 노트](../../03-트랜잭션과-데이터-정합성/학습%20노트.md)를 읽고 `OrderTransactionTest`에서 정상 처리·예외 전달·예외 잡기의 DB 결과를 비교한다. 테스트 전용 서비스와 데이터로 실행한다.
- 다음 시작 위치: `ordering`, `inventory`
- 다음 과제: 재고 1개에 두 개의 구매 요청을 동시에 보낸다. 조건부 갱신·락 중 해결책을 선택하고 근거를 남긴다.
- 확장: 동일 주문 요청의 중복 방지, 가짜 결제 API의 타임아웃과 결과 조회·복구를 추가한다.
- 연결: [트랜잭션](../../03-트랜잭션과-데이터-정합성/공부%20목표.md), [외부 API](../../05-HTTP-외부-API와-실패-처리/공부%20목표.md)

## 3. 전시 도메인

- 시작 위치: `display`
- 할 일: 카테고리·기획전·배너·진열 항목을 상품 원본과 나눈다. 노출 기간 경계와 동시 순서 변경을 검증한다.
- 확장: 상품 원본과 별도의 조회 모델을 만들고, 중복·역순 이벤트와 재구성을 다룬다. 원본과 아웃박스 기록은 같은 트랜잭션에 저장한다.
- 연결: [전시 목표와 세부 과제](../../08-전시-도메인/공부%20목표.md), [아키텍처](../../10-아키텍처와-도메인-경계/공부%20목표.md)

## 4. 랭킹

- 시작 위치: `ranking`
- 할 일: 최근 24시간 판매량과 취소 데이터를 직접 준비하고 예상 순위를 계산한다. SQL 집계와 결과를 대조한다.
- 확장: 완료된 집계 버전 공개, 집계 중 장애, 중복·지연 사건, 조회 저장 구조를 비교한다.
- 연결: [랭킹 목표](../../11-랭킹-도메인/공부%20목표.md), [SQL](../../04-SQL-인덱스와-데이터-접근/공부%20목표.md)

## 5. 검색

- 시작 위치: `search`
- 할 일: 검색어와 기대 상품 평가셋을 작성하고 DB 기반 검색·필터·정렬을 만든다.
- 확장: 전문 검색 엔진과 품질을 비교하고, 원본 변경의 반영 지연·삭제·재색인·페이지 일관성을 검증한다.
- 연결: [검색 목표](../../12-검색-도메인/공부%20목표.md)

## 전 과정: 관찰과 기록

로그·SQL·지표를 확인하고 구현 전후를 같은 조건으로 비교한다. 각 주제의 폴더에 `학습 노트.md`와 `실습 기록.md`를 추가한다. 기록에는 문제, 재현 조건, 예상 결과, 실제 결과, 대안과 비용, 남은 질문을 남긴다.

관련 개념을 처음부터 모두 외우기보다 현재 변경에 필요한 [Java 기본기](../../01-Java-기본기와-실행-원리/공부%20목표.md)와 [운영·성능·보안](../../07-운영-성능과-보안/공부%20목표.md)을 함께 확인한다.
