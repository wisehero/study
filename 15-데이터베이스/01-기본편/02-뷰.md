# 2장 뷰

자주 쓰는 복잡한 SELECT를 매번 다시 쓰는 대신 이름을 붙여 저장해 두고 테이블처럼 쓸 수 있다. 이것이 뷰(view)다. 이번 장에서는 **뷰가 무엇을 저장하는지, 어떻게 만들고 고치는지, 언제 쓰고 언제 피하는지**를 정리한다. 강의 섹션 7에 해당한다. [뷰 사용](https://dev.mysql.com/doc/refman/8.4/en/views.html)

예시는 회원(`member`), 상품(`product`), 주문(`orders`) 테이블을 쓴다. 주문 한 건은 회원 한 명이 상품 하나를 여러 개 산 기록이다.

```sql
CREATE TABLE member  (member_id BIGINT PRIMARY KEY, name VARCHAR(50) NOT NULL, grade VARCHAR(10) NOT NULL);
CREATE TABLE product (product_id BIGINT PRIMARY KEY, name VARCHAR(100) NOT NULL, price INT NOT NULL);
CREATE TABLE orders  (order_id BIGINT PRIMARY KEY, member_id BIGINT NOT NULL, product_id BIGINT NOT NULL,
                      quantity INT NOT NULL, status VARCHAR(20) NOT NULL, ordered_at DATETIME NOT NULL);
```

## 1 뷰: 이름을 붙여 저장한 SELECT

**뷰는 데이터가 아니라 SELECT 문을 저장한 것이고, 조회할 때마다 그 SELECT를 실행해 결과를 만든다.** 그래서 뷰를 가상 테이블(virtual table)이라고도 부른다. 뷰를 조회하는 쪽에서는 테이블과 똑같이 `SELECT ... FROM 뷰이름`으로 쓴다. [뷰 사용](https://dev.mysql.com/doc/refman/8.4/en/views.html)

```sql
-- 주문 목록 화면에서 매번 쓰는 조인
SELECT o.order_id, m.name AS member_name, p.name AS product_name,
       o.quantity, p.price * o.quantity AS total_price, o.ordered_at
FROM orders o
JOIN member  m ON m.member_id  = o.member_id
JOIN product p ON p.product_id = o.product_id;
```

이 조인을 뷰로 만들어 두면 화면 쪽 쿼리는 `SELECT * FROM order_detail WHERE ...`처럼 짧아진다. **뷰가 데이터를 따로 들고 있지 않으므로, 원래 테이블의 데이터가 바뀌면 뷰의 조회 결과도 바로 바뀐다.**

## 2 뷰 생성, 조회, 수정, 삭제

### 생성과 조회

```sql
CREATE VIEW order_detail AS
SELECT o.order_id, m.name AS member_name, p.name AS product_name,
       o.quantity, p.price * o.quantity AS total_price, o.ordered_at
FROM orders o
JOIN member  m ON m.member_id  = o.member_id
JOIN product p ON p.product_id = o.product_id;

SELECT * FROM order_detail WHERE member_name = '김철수';
```

뷰를 만들 때 알아 둘 규칙은 다음과 같다. [CREATE VIEW](https://dev.mysql.com/doc/refman/8.4/en/create-view.html)

- **뷰와 테이블은 같은 이름 공간을 쓴다.** 같은 DB 안에 같은 이름의 테이블과 뷰를 둘 수 없다.
- 뷰의 컬럼 이름도 중복될 수 없다. 계산식 컬럼에는 `AS total_price`처럼 별칭을 붙인다.
- **뷰의 정의는 만든 시점에 고정된다.** `SELECT *`로 만든 뷰는 나중에 테이블에 추가한 컬럼을 보여 주지 않는다. 뷰가 쓰던 컬럼이나 테이블을 지우면, 경고 없이 지워지고 그 뒤 뷰를 조회할 때 오류가 난다. [뷰의 제약](https://dev.mysql.com/doc/refman/8.4/en/view-restrictions.html)
- 만들어진 뷰의 정의는 `SHOW CREATE VIEW order_detail;`로 확인한다. [SHOW CREATE VIEW](https://dev.mysql.com/doc/refman/8.4/en/show-create-view.html)

### 수정과 삭제

뷰의 SELECT를 바꾸는 방법은 두 가지다. `CREATE OR REPLACE VIEW`는 뷰가 없으면 만들고 있으면 바꾼다. `ALTER VIEW`는 이미 있는 뷰만 바꾼다. [CREATE VIEW](https://dev.mysql.com/doc/refman/8.4/en/create-view.html), [ALTER VIEW](https://dev.mysql.com/doc/refman/8.4/en/alter-view.html)

```sql
CREATE OR REPLACE VIEW order_detail AS
SELECT o.order_id, m.name AS member_name, p.name AS product_name,
       o.quantity, p.price * o.quantity AS total_price, o.status, o.ordered_at
FROM orders o
JOIN member  m ON m.member_id  = o.member_id
JOIN product p ON p.product_id = o.product_id;

DROP VIEW IF EXISTS order_detail;
```

**`DROP VIEW`는 뷰만 지우고 원래 테이블의 데이터는 그대로 둔다.** MySQL 8.4에서는 여러 뷰를 한 번에 지울 때 그중 하나라도 없으면 아무것도 지우지 않고 오류를 낸다. 8.3 이전에는 있는 뷰는 지우고 오류를 냈으므로 동작이 다르다. `IF EXISTS`를 붙이면 없는 뷰는 건너뛴다. [DROP VIEW](https://dev.mysql.com/doc/refman/8.4/en/drop-view.html)

### 뷰로 데이터를 바꿀 수 있는가

**뷰의 한 행이 원래 테이블의 한 행과 정확히 대응할 때만 뷰를 통해 UPDATE, DELETE, INSERT를 할 수 있다.** 다음 중 하나라도 들어 있으면 뷰로 데이터를 바꿀 수 없다. [갱신 가능한 뷰](https://dev.mysql.com/doc/refman/8.4/en/view-updatability.html)

- 집계 함수(`SUM`, `COUNT` 등)와 윈도 함수.
- `DISTINCT`, `GROUP BY`, `HAVING`.
- `UNION`, `UNION ALL`.
- SELECT 목록 안의 서브쿼리 등 일부 구조.

조인한 뷰는 내부 조인일 때만 UPDATE가 가능한 경우가 있고, 그때도 한 번에 테이블 하나의 컬럼만 바꿀 수 있다. 실무에서 뷰는 대부분 조회용으로 쓰고, 데이터 변경은 원래 테이블에 직접 하는 편이 의도가 분명하다.

뷰로 데이터를 바꾸도록 허용할 때는 `WITH CHECK OPTION`을 붙일 수 있다. 붙이면 **뷰의 WHERE 조건을 벗어나는 행을 뷰로 넣거나, 보이던 행을 조건 밖으로 바꾸는 것을 막는다.** [WITH CHECK OPTION](https://dev.mysql.com/doc/refman/8.4/en/view-check-option.html)

```sql
CREATE VIEW vip_member AS
SELECT member_id, name, grade FROM member WHERE grade = 'VIP'
WITH CHECK OPTION;

-- 오류: 바꾸면 이 뷰에서 보이지 않게 되는 행이다
UPDATE vip_member SET grade = 'BASIC' WHERE member_id = 1;
```

## 3 뷰의 장점과 단점

### 장점

- **복잡한 쿼리를 이름 하나로 감춘다.** 여러 화면과 배치에서 같은 조인을 쓴다면 뷰 하나로 모으고, 조인 조건이 바뀌면 뷰만 고친다.
- **보여 줄 컬럼과 행만 내보낸다.** 회원 테이블에 전화번호나 주소가 있어도 뷰에는 이름과 등급만 담아, 통계 담당자에게 뷰 조회 권한만 줄 수 있다. 뷰를 실행할 때 어떤 계정의 권한으로 테이블을 읽을지는 `SQL SECURITY` 절로 정하며 기본값은 뷰를 만든 계정(`DEFINER`)이다. [CREATE VIEW](https://dev.mysql.com/doc/refman/8.4/en/create-view.html)
- **테이블 구조가 바뀌어도 기존 쿼리를 지킬 수 있다.** 테이블을 둘로 나눠도 같은 이름과 컬럼의 뷰를 만들어 두면 기존 조회 쿼리는 그대로 동작한다.

### 단점

- **뷰는 성능을 높여 주지 않는다.** 뷰는 결과를 저장하지 않으므로 조회할 때마다 원래 SELECT를 실행한다. MySQL 8.4의 `CREATE VIEW`에는 결과를 미리 저장해 두는 구체화된 뷰(materialized view)를 만드는 문법이 없다.
- **뷰에는 인덱스를 만들 수 없다.** MySQL이 뷰를 바깥 쿼리와 합쳐서 실행하는 MERGE 방식이면 원래 테이블의 인덱스를 쓸 수 있다. 하지만 집계나 UNION 때문에 결과를 임시 테이블에 먼저 담는 TEMPTABLE 방식이면, 바깥 쿼리의 조건에는 원래 테이블의 인덱스를 쓰지 못한다. [뷰 처리 방식](https://dev.mysql.com/doc/refman/8.4/en/view-algorithms.html), [뷰의 제약](https://dev.mysql.com/doc/refman/8.4/en/view-restrictions.html)
- **실제 쿼리가 숨어서 느린 원인을 찾기 어렵다.** `SELECT * FROM order_detail` 한 줄 뒤에 조인 세 개가 있다. 뷰 위에 뷰를 쌓으면 더 찾기 어렵다.
- **테이블을 바꿀 때 뷰가 조용히 깨진다.** 컬럼을 지우거나 이름을 바꿔도 경고가 없고, 뷰를 조회할 때 오류가 난다. 테이블을 바꾼 뒤에는 `CHECK TABLE 뷰이름`으로 확인한다. [뷰의 제약](https://dev.mysql.com/doc/refman/8.4/en/view-restrictions.html)

**뷰는 쿼리를 정리하고 노출 범위를 좁히는 도구이지, 쿼리를 빠르게 하는 도구가 아니다.** 실무에서는 앱 코드(JPA 리포지토리나 쿼리 파일)에 쿼리를 두는 경우가 많아, 뷰를 쓰면 쿼리가 DB와 앱 두 곳으로 나뉜다는 점도 함께 따진다.

## 이해를 확인할 질문

1. 뷰는 데이터를 저장하는가? 원래 테이블이 바뀌면 뷰의 결과는 어떻게 되는가?
2. `SELECT *`로 만든 뷰는 테이블에 컬럼을 추가하면 새 컬럼을 보여 주는가?
3. `GROUP BY`가 들어간 뷰로 UPDATE를 할 수 없는 이유는 무엇인가?
4. 뷰를 쓰면 쿼리가 빨라지는가? MERGE와 TEMPTABLE 방식에서 인덱스 사용은 어떻게 다른가?
