# 기본편 공부 목표

> 상태: 학습 중 · 작성일: 2026-10-18

## 학습 목적

조인과 집계 같은 기본 SQL은 이미 쓰고 있으므로, 실무에서 성능과 데이터 정확성을 좌우하는 주제만 골라 공부한다. 인덱스가 쓰이는 조건과 쓰이지 않는 조건을 근거를 들어 설명하고, 제약 조건과 트랜잭션으로 데이터가 깨지지 않게 지키는 방법을 정리한다. 이 내용은 [성능 최적화](../02-성능-최적화/공부%20목표.md) 강의로 넘어가기 위한 바탕이 된다.

## 학습 자료

- 강의: [김영한의 실전 데이터베이스 - 기본편](https://www.inflearn.com/course/김영한-실전-데이터베이스-기본편)
- 분량: 13개 섹션, 84강, 약 13시간 40분. 이번 범위인 6개 섹션은 40강, 약 6시간 26분.
- 강의의 선수 과목: 김영한의 실전 데이터베이스 입문.
- 실습 DB: MySQL 8.4, InnoDB 저장 엔진.
- 강의 영상의 스크립트가 없어 노트는 강의 제목을 뼈대로 하고 [MySQL 8.4 공식 문서](https://dev.mysql.com/doc/refman/8.4/en/)를 근거로 쓴다. 강의를 들으며 노트와 다른 설명이 나오면 노트를 고친다.

## 범위와 선행 지식

- 이번 범위: 섹션 5(UNION), 7(뷰), 8(인덱스1), 9(인덱스2), 10(데이터 무결성), 11(트랜잭션).
- 제외한 범위: 섹션 1(강의 소개), 2~3(조인), 4(서브쿼리), 6(CASE 문), 12(저장 프로시저·함수·트리거), 13(다음으로). 사용자가 범위에서 뺐으며, 섹션 1~3은 이미 익숙한 기초라서 제외했다.
- 선행 지식: SELECT, 조인, GROUP BY 등 기본 SQL, 기본키의 개념.
- 깊게 들어가는 내용: B+Tree 내부 구조, 클러스터드·세컨더리 인덱스, 옵티마이저 비용, 실행 계획 상세는 [성능 최적화](../02-성능-최적화/공부%20목표.md)에서 다룬다. 잠금과 동시성 제어는 [트랜잭션과 데이터 정합성](../../03-트랜잭션과-데이터-정합성/공부%20목표.md)에서 다룬다.

## 강의 목차별 목표

### 섹션 5. UNION

- [ ] UNION과 UNION ALL의 차이를 설명하고, 중복 제거가 필요 없을 때 UNION ALL을 고르는 이유를 말한다.
- [ ] UNION의 컬럼 수·이름·타입 규칙을 설명한다.
- [ ] 합친 결과 전체를 정렬하는 방법과, 각 SELECT 안의 ORDER BY가 최종 순서를 보장하지 않는 이유를 설명한다.

### 섹션 7. 뷰(View)

- [ ] 뷰가 데이터가 아니라 SELECT를 저장한 것임을 설명한다.
- [ ] 뷰를 만들고, 조회하고, 고치고, 지운다.
- [ ] 뷰로 데이터를 바꿀 수 없는 경우를 설명한다.
- [ ] 뷰가 성능을 높여 주지 않는 이유와, 쿼리를 정리하고 노출 범위를 좁히는 쓰임을 구분한다.

### 섹션 8. 인덱스1

- [ ] 100만 건 샘플 데이터에서 인덱스가 없을 때와 있을 때의 실행 계획을 비교한다.
- [ ] B-Tree 인덱스가 동등 비교, 범위 검색, 정렬에 유리한 이유를 트리 구조로 설명한다.
- [ ] 인덱스를 만들고, `SHOW INDEX`로 확인하고, 지운다.
- [ ] 컬럼 가공, 타입 불일치, `LIKE '%...'`가 인덱스 사용을 막는 이유를 설명한다.
- [ ] 인덱스로 정렬을 생략하는 경우와 `Using filesort`가 나는 경우를 구분한다.

### 섹션 9. 인덱스2

- [ ] 옵티마이저가 여러 인덱스 중 하나를 고르거나 풀 테이블 스캔을 고르는 기준을 설명한다.
- [ ] 커버링 인덱스가 실제 행 탐색을 생략하는 원리를 설명하고, 실행 계획의 `Using index`로 확인한다.
- [ ] 복합 인덱스에서 왼쪽 컬럼부터 써야 하는 이유와, 범위 조건 뒤의 컬럼이 탐색에 쓰이지 않는 이유를 설명한다.
- [ ] 쿼리를 보고 등호·범위·정렬 조건에 맞는 복합 인덱스의 컬럼 순서를 정한다.
- [ ] 인덱스의 쓰기 비용과 저장 비용을 설명하고, 보이지 않는 인덱스로 안전하게 지우는 절차를 정리한다.

### 섹션 10. 데이터 무결성

- [ ] 앱 검증만으로 데이터 무결성을 지키기 어려운 이유를 설명한다.
- [ ] NOT NULL, UNIQUE, PRIMARY KEY, DEFAULT가 각각 막는 것을 구분한다.
- [ ] 외래 키의 참조 동작(RESTRICT, CASCADE, SET NULL)을 비교하고, 외래 키를 걸지 판단하는 기준을 정리한다.
- [ ] CHECK 제약으로 가격과 재고 규칙을 걸고, NULL이 들어간 조건의 결과를 설명한다.

### 섹션 11. 트랜잭션

- [ ] 여러 SQL을 트랜잭션으로 묶어야 하는 이유를 주문 처리 예로 설명한다.
- [ ] 자동 커밋, 오류가 난 문장의 롤백 범위, DDL의 묵시적 커밋을 설명한다.
- [ ] ACID 각 속성을 InnoDB가 어떤 장치로 지키는지 연결한다.
- [ ] 네 가지 격리 수준에서 같은 SELECT가 무엇을 읽는지 설명하고, 두 세션으로 직접 재현한다.

## 실습 과제

1. 100만 건 상품 테이블에서 인덱스 생성 전후의 실행 계획(`type`, `key`, `rows`, `Extra`)과 실행 시간을 기록한다.
2. 같은 쿼리에 (category, price)와 (price, category) 인덱스를 각각 걸어 실행 계획을 비교하고, 어느 쪽이 나은지 근거를 쓴다.
3. 회원·주문 테이블에 외래 키와 CHECK 제약을 걸고, 제약을 어기는 INSERT·UPDATE·DELETE가 어떤 오류를 내는지 기록한다.
4. MySQL 클라이언트 두 개를 열어 READ COMMITTED와 REPEATABLE READ에서 같은 시나리오를 실행하고, 각 SELECT의 결과를 표로 남긴다.

## 스스로 설명할 질문

- UNION 대신 UNION ALL을 써도 되는지 어떻게 판단하는가?
- 인덱스가 있는데 쓰이지 않는다면 무엇부터 의심하는가?
- 복합 인덱스의 컬럼 순서는 어떤 기준으로 정하는가?
- 외래 키를 걸지 않기로 했다면 참조 무결성은 누가 지키는가?
- REPEATABLE READ에서 SELECT로 읽은 값과 UPDATE가 보는 값이 다를 수 있는 이유는 무엇인가?

## 완료 기준

- [ ] 6개 섹션의 강의를 듣고, 노트 내용 중 강의와 다른 부분을 고친다.
- [ ] 실습 과제 네 가지의 결과를 실행 계획과 오류 메시지, 조회 결과로 남긴다.
- [ ] 스스로 설명할 질문에 노트를 보지 않고 답한다.
