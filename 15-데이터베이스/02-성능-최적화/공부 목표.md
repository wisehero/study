# 성능 최적화 공부 목표

> 상태: 학습 중 · 작성일: 2026-10-18

## 학습 목적

데이터가 쌓이면서 느려진 쿼리의 원인을 실행 계획과 측정값으로 찾고, 인덱스·쿼리 구조를 바꿔 개선한 결과를 전후 비교로 증명한다. 인덱스를 외워서 붙이는 것이 아니라, 저장 구조와 옵티마이저의 판단 기준을 이해한 상태에서 설계한다.

## 학습 자료

- 강의: [김영한의 실전 데이터베이스 - 성능 최적화, 실행 계획과 인덱스 완전 정복](https://www.inflearn.com/course/김영한-실전-데이터베이스-성능최적화)
- 분량: 17개 섹션, 104강, 약 21시간 10분. 게시일 2026-07-28.
- 강의의 선수 과목: 김영한의 실전 데이터베이스 기본편.
- 강의의 실습 DB: MySQL 8.4, InnoDB 저장 엔진.

## 범위와 선행 지식

- 이번 범위: MySQL 구조, 실행 계획(EXPLAIN, EXPLAIN ANALYZE), B+Tree 인덱스, 클러스터드·세컨더리 인덱스, 인덱스 심화 기능, 옵티마이저와 통계, 조인·정렬·페이징·그룹핑 최적화, 네 번의 실전 튜닝.
- 후속 범위: 같은 문제를 이 저장소의 PostgreSQL 17.6 실습 DB에서 재현하고 두 DB의 차이를 비교한다.
- 선행 지식: SELECT·조인·집계 등 기본 SQL, 기본키와 인덱스의 개념.
- 범위 밖: 트랜잭션·격리 수준·락은 [트랜잭션과 데이터 정합성](../../03-트랜잭션과-데이터-정합성/공부%20목표.md)에서 다룬다.

## 강의 목차별 목표

### 섹션 3. 데이터베이스 성능과 MySQL 아키텍처

- [ ] MySQL 서버 계층과 InnoDB 저장 엔진 계층이 각각 하는 일을 구분한다.
- [ ] InnoDB가 데이터를 페이지 단위로 저장하고 버퍼 풀에 올려 읽는 방식을 설명한다.
- [ ] 쿼리 한 건이 파싱, 최적화, 실행을 거쳐 결과가 되는 흐름을 설명한다.

### 섹션 4. 실행 계획 1: EXPLAIN

- [ ] EXPLAIN 결과에서 접근 유형(type)을 읽고, 빠른 순서와 각 유형이 나오는 조건을 설명한다.
- [ ] possible_keys, key, key_len, ref로 어떤 인덱스를 어디까지 사용했는지 판단한다.
- [ ] rows, filtered로 옵티마이저가 예상한 처리량을 읽는다.
- [ ] Extra 컬럼의 주요 값(Using index, Using where, Using filesort, Using temporary 등)의 의미를 설명한다.

### 섹션 5. 실행 계획 2: EXPLAIN ANALYZE

- [ ] EXPLAIN ANALYZE가 쿼리를 실제로 실행한다는 점과 EXPLAIN과의 차이를 설명한다.
- [ ] 실행 통계에서 단계별 실제 시간, 행 수, 반복 횟수를 읽는다.
- [ ] Top-N 최적화와 파이프라인 방식 실행이 조기 종료로 이어지는 조건을 설명한다.
- [ ] 예상 행 수와 실제 행 수의 차이가 클 때 무엇을 의심할지 정리한다.

### 섹션 6. 실전 튜닝 1: 풀 테이블 스캔과 복합 인덱스 기초

- [ ] 관리자 주문 조회의 풀 테이블 스캔을 진단하고, 복합 인덱스로 개선한 결과를 전후 비교로 기록한다.

### 섹션 7. 인덱스 내부 구조 1: B+Tree

- [ ] B-Tree와 B+Tree의 구조 차이를 그림으로 설명한다.
- [ ] B+Tree가 범위 조회와 디스크 페이지 읽기에 유리한 이유를 설명한다.

### 섹션 8. 인덱스 내부 구조 2: 클러스터드·세컨더리 인덱스

- [ ] InnoDB에서 기본키가 곧 데이터의 저장 순서가 되는 클러스터드 인덱스 구조를 설명한다.
- [ ] 순차 PK와 랜덤 PK가 삽입 성능과 저장 공간에 주는 영향을 비교하고, 실무 PK 설계 기준을 정리한다.
- [ ] 세컨더리 인덱스가 PK를 거쳐 데이터를 찾는 과정과 커버링 인덱스로 이 과정을 생략하는 원리를 설명한다.
- [ ] 랜덤 I/O와 순차 I/O의 비용 차이를 실습으로 확인한다.
- [ ] MySQL, Oracle, PostgreSQL의 테이블·인덱스 저장 방식 차이를 정리한다.

### 섹션 9. 실전 튜닝 2: Using filesort와 조기 종료

- [ ] 상품 검색 쿼리의 Using filesort를 진단하고, 인덱스 정렬과 조기 종료로 개선한 결과를 기록한다.

### 섹션 10. 인덱스 심화 1: ICP, 커버링, 스킵 스캔

- [ ] ICP(Index Condition Pushdown)가 저장 엔진 단계에서 조건을 걸러 내는 원리와 적용 조건을 설명한다.
- [ ] 커버링 인덱스의 효과를 대용량 데이터에서 직접 측정한다.
- [ ] 인덱스 스킵 스캔이 복합 인덱스의 선두 컬럼 조건 없이 동작하는 조건과 한계를 설명한다.

### 섹션 11. 인덱스 심화 2: 머지, MRR, 신기능, 힌트, 운영

- [ ] 인덱스 머지가 필요한 상황과, 복합 인덱스보다 불리할 수 있는 이유를 설명한다.
- [ ] MRR(Multi-Range Read)이 랜덤 I/O를 줄이는 방식을 설명한다.
- [ ] 함수 기반 인덱스, 인덱스 숨기기, 내림차순 인덱스의 쓰임을 정리한다.
- [ ] 옵티마이저 힌트를 써야 하는 경우와 남용했을 때의 위험을 정리한다.
- [ ] 인덱스가 쓰기 성능과 저장 공간에 주는 비용을 설명한다.

### 섹션 12. 옵티마이저와 히스토그램

- [ ] 비용 기반 옵티마이저가 실행 계획을 고르는 기준을 설명한다.
- [ ] 인덱스가 있는데도 사용되지 않는 원인을 통계 정보 관점에서 진단한다.
- [ ] 히스토그램이 필요한 데이터 분포를 설명하고, 생성 전후 실행 계획을 비교한다.

### 섹션 13. 조인 최적화

- [ ] Nested Loop Join의 동작과, 드리븐 테이블 쪽 인덱스가 성능을 좌우하는 이유를 설명한다.
- [ ] 인덱스가 없을 때 해시 조인이 선택되는 조건을 설명한다.
- [ ] 옵티마이저가 드라이빙 테이블을 정하는 기준을 설명한다.

### 섹션 14. 실전 튜닝 3: 조인 랜덤 액세스와 커버링 인덱스

- [ ] 회원별 주문 통계 쿼리의 조인 랜덤 액세스를 진단하고, 커버링 인덱스로 개선한 결과를 기록한다.

### 섹션 15. 정렬, 페이징, 그룹핑 최적화

- [ ] filesort가 메모리에서 끝나는 경우와 디스크를 쓰는 경우를 구분한다.
- [ ] 인덱스 정렬과 지연 조인(deferred join)으로 정렬·페이징 비용을 줄이는 방법을 설명한다.
- [ ] OFFSET 페이징이 뒤 페이지로 갈수록 느려지는 이유와 커서 기반 페이징의 설계 조건을 설명한다.
- [ ] GROUP BY가 인덱스를 사용하는 경우와 임시 테이블을 만드는 경우를 구분한다.

### 섹션 16. 실전 튜닝 4: 스트리밍 집계와 사전 집계 테이블

- [ ] GROUP BY가 만드는 임시 테이블을 인덱스 정렬 변경으로 없애고, 사전 집계 테이블과 비교한다.
- [ ] 네 번의 실전 튜닝에서 쓴 진단 순서를 하나의 점검 절차로 정리한다.

## 실습 과제

1. 강의의 실전 튜닝 네 가지를 MySQL 8.4에서 따라 하고, 개선 전후의 실행 계획과 실행 시간을 같은 조건에서 기록한다.
2. 실전 튜닝 중 최소 하나를 PostgreSQL 17.6에서 재현하고, 실행 계획 표기와 옵티마이저 선택의 차이를 기록한다.
3. 인덱스를 추가했는데도 사용되지 않는 경우를 직접 만들고, 원인을 통계 정보와 실행 계획으로 설명한다.

## 스스로 설명할 질문

- 느린 쿼리를 받았을 때 실행 계획에서 무엇부터 확인하는가?
- 세컨더리 인덱스로 조회하는데 왜 PK 인덱스까지 다시 읽는가?
- 복합 인덱스의 컬럼 순서는 어떤 기준으로 정하는가?
- 옵티마이저가 인덱스를 두고 풀 테이블 스캔을 고르는 것은 언제 합리적인가?

## 완료 기준

- [ ] 실행 계획의 주요 컬럼을 자신의 말로 설명하고, 예제 쿼리에서 읽어 낸다.
- [ ] 실전 튜닝 네 가지의 개선 전후 결과를 측정값과 함께 기록한다.
- [ ] 인덱스가 쓰기 비용, 저장 공간, 정렬·페이징 정확성에 주는 영향을 설명한다.
- [ ] MySQL에서 배운 내용 중 PostgreSQL에서 달라지는 점을 최소 하나 실험으로 확인한다.
